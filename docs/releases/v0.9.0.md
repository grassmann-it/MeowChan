# oChan 0.9.0 — release-notes draft

**Status: unreleased, in preparation.** Final native package acceptance is still open. These notes describe the implemented desktop update and are a draft for the GitHub release.

0.9.0 introduces a new Avalonia interface for watching 4chan and 8kun threads and boards. It builds on the verified downloads, shared queue and durable sessions released in 0.8.0. The independently usable `libochan` library and .NET 10 baseline remain in place.

## Highlights

- **New cat icon.** A photographic cat-head cutout replaces the previous app and tray branding, including Windows icons and the macOS app bundle.
- **Barebones, Simple and Advanced.** The footer lists views in this order, with Simple as the default. Advanced adds separate thread-ID, status, queued-media and active-media columns. Barebones provides a smaller, denser window. All three operate on the same running session and retain the core controls.
- **Real Downloads and Settings pages.** Bottom navigation changes the work area within a shared shell. Input, selection, details, settings drafts and running downloads survive navigation. Save/Cancel stay on Settings; About remains in the menu.
- **Compact workspace and readable icons.** Grouped table cells give downloads more space. Details start closed; import results expand within the URL intake panel. Action icons follow the menu's theme. Shared button states, primary-label contrast, keyboard focus and aligned Settings actions now follow the same Dark/Light styling.
- **Dark/Light and language preferences.** Choose theme, density and built-in English or German. Additional languages can be supplied as plain JSON packs in the active profile's `LanguagePacks` directory. Missing translations fall back to English; invalid or unavailable packs produce a warning without preventing startup.
- **Multiple URLs in one import.** Separate thread/board URLs with commas or newlines. Add or Enter processes them through the existing admission path and reports each result. Invalid entries do not prevent later entries from being handled. Failed lists remain available for correction.
- **Useful thread and board details.** Inspect the selected URL, assigned download directory, source state and current errors. Thread details also show saved/known media and queued/active jobs. Open the folder or browser, copy the URL or remove the watch from the same panel.
- **Copy URLs for reuse.** Copy one URL or all watched thread and board URLs as a newline-separated list, ready to import again.

## Controls and behavior changes

**Double-click now opens details instead of opening the folder.** Folder opening remains a separate button/context action. Details appear beside wide tables and overlay narrow ones; Escape closes them.

Enter in the URL field starts an import; Shift+Enter inserts a newline. Ctrl+L/Cmd+L returns to Downloads and focuses the retained field. Empty Add, the tray import action and Ctrl+V/Cmd+V outside text fields in the main window read the clipboard once. Normal paste remains available inside text fields.

Imports preserve any input edited while they run. Explicit input clears only when all entries were added or already present and the input has not changed. The result report covers the latest import; it is not a persistent activity history. Copy all includes both thread and board watches, regardless of the active tab.

Progress means **saved media / currently known media**. The known count can grow, and 100% does not end monitoring. Queued/active counts refer to media jobs. “Archived” describes the remote thread state, not a local HTML archive.

## Upgrading from 0.8.0

Existing profile locations, watched URLs, settings and assigned download paths remain usable. Back up the profile before replacing a release. Missing appearance fields receive **Simple, Dark, English and normal density** defaults. Theme, language, view and density are saved in `settings.json`; window geometry, column layout and details-panel width are not saved across restarts.

Settings changes require a successful Save; Cancel reloads confirmed values. Both actions stay on Settings. Page navigation preserves pending edits. Theme and view changes made in the footer save immediately and synchronize only the corresponding draft field, preserving unrelated edits and validation errors. Changing the output root continues to leave existing watch destinations intact, including later threads discovered by an existing board.

English and German are included. Add or edit optional language packs while the app is closed, then restart and select the language in Settings. The [language-pack instructions](../../Desktop/Localization/README.md) describe the format. Technical provider and exception messages can remain untranslated.

The desktop now uses Avalonia 12.1.4, with matching Actipro 26.2.0 and DataGrid 12.1.2 packages. This includes the upstream fix for late Linux DBus tray registration after disposal. The public `libochan` API does not change for this interface replacement. Source builds and library consumers continue to require .NET 10; self-contained desktop archives include the runtime.

## Packages and remaining validation

The package targets remain Windows x64, Linux x64/Arm64 and macOS Intel/Apple Silicon. Extract the whole archive and retain its native libraries, notices and documentation. macOS archives contain an unsigned, non-notarized `oChan.app`. Linux packages require glibc, native graphics/font dependencies including `libdbus-1` and an X11 or XWayland desktop.

Final release acceptance must identify the source commit and archive hashes and record native workflows in freshly extracted packages on the promised OS/CPU matrix. That includes download/removal/restore, clipboard/folder actions, tray fallback, shutdown, small windows and display scaling. The successful 0.8.0 CI runs remain historical evidence and do not validate this UI update. See the [platform validation record](../platform-support.md) for the current evidence and open checks.

Pause/resume, search/filtering, drag-and-drop, archive/reader views, rules, import/export tools, TUI/daemon clients and dynamic plugin loading are outside 0.9.0. Providers can already be supplied explicitly through the library contracts. The scope of 1.0 remains a later decision.
