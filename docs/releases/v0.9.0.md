# MeowChan 0.9.0 — release-notes draft

**Status: unreleased; 0.9.0 is in preparation.** Complete the remaining
0.9.0 fixes and checks first; one Windows test build for user testing will follow
that work. No further intermediate preview release is planned. The published
[Windows x64 Preview 3](https://github.com/tfgrass/MeowChan/releases/tag/v0.9.0-preview.3)
includes .NET 10 and VLC and remains the existing historical test build. Current
source changes, including the Barebones default, transfer speed display,
reader/gallery window controls, reader loading/position fixes and persistent
offline video previews, are not included in published Preview 3. The planned
Windows test build has not been built or published.

These notes describe the current source candidate. Final acceptance of the five
native packages remains open; source/Linux media checks do not establish
Windows/macOS packaged playback, real audio or hardware acceptance. Stable 0.9.0
remains unreleased.

0.9.0 renames the product to **MeowChan** and introduces a new Avalonia interface for watching 4chan and 8kun threads and boards. It builds on the verified downloads, shared queue and durable sessions released in 0.8.0. The independently usable library is now named `libmeowchan`; the .NET 10 baseline remains.

## Highlights

- **Archive and shared gallery.** Read captured posts, search local content, follow saved quotes/backlinks, or browse saved-media rows/tiles. Double-click thread rows/cards for the large reader; use Shift+Enter or the context menu for their gallery; right-click Archive entries for Read posts, Open in gallery and Export as HTML. Images of results freezes all found threads in current sort order across result pages, including images outside matching posts. Saved-media navigation preserves its sort and version filter. The window-wide viewer provides arrows, Fit/1:1, zoom/pan and optional saved-post context.
- **Durable missing-media policy.** Consecutive media 404s pause 15/30/60/120/240 minutes, then at least 240. A terminal source has a fixed 12-hour follow-up from its first durably recorded end; restart/pause do not extend it. Completion can retain missing 404 media; other exhausted errors require intervention. Check-now respects pauses. Manual media retry grants one outer attempt through the normal queue without resetting history or opening a new terminal window.
- **Portable and repeatable HTML export.** A compact dialog offers a new folder or explicit update of a recognized earlier export, with separate Open previous export and current-result Open folder actions. Modified/extra files, associated legacy exports or reduced new output require preserving the old folder as a backup. Only saved, verified matching media are copied; export never downloads content.

- **Check now and separate media retry.** Downloads and Diagnostics can request a check on the exact watch; ordinary Check now respects media due times. Retry missing media is a separate, single-attempt repair action with normal queue/source limits, including repair of completed threads without restarting source monitoring.
- **Persistent Pause/Resume.** Pause in the header or menu now cancels active source checks and transfers, with Pausing visible until cancellation settles. Resume retries unfinished work; verified files, retry history and terminal deadlines remain intact. This replaces the earlier behavior that let active work finish.

- **New cat icon.** A photographic cat-head cutout replaces the previous app and tray branding, including Windows icons and the macOS app bundle.
- **Barebones, Simple and Advanced.** The footer lists views in this order. Builds after Windows Preview 3 default new profiles and missing/invalid view preferences to Barebones, preserving every valid saved choice. Published Preview 3 (`a98759e`) still defaults to Simple and supports switching manually. Advanced adds separate thread-ID, status, queued-media and active-media columns. Barebones provides a smaller, denser window. All three operate on the same running session and retain the core controls.
- **Real Downloads and Settings pages.** Bottom navigation changes the work area within a shared shell. Input, selection, details, settings drafts and running downloads survive navigation. Save/Cancel stay on Settings; About remains in the menu.
- **Compact workspace and readable icons.** Grouped table cells give downloads more space. Details start closed; import results expand within the URL intake panel. Action icons follow the menu's theme. Shared button states, primary-label contrast, keyboard focus and aligned Settings actions now follow the same Dark/Light styling.
- **Dark/Light and language preferences.** Choose theme, density and built-in English or German. Additional languages can be supplied as plain JSON packs in the active profile's `LanguagePacks` directory. Missing translations fall back to English; invalid or unavailable packs produce a warning without preventing startup.
- **Multiple URLs in one import.** Separate thread/board URLs with commas or newlines. Add or Enter processes them through the existing admission path and reports each result. Invalid entries do not prevent later entries from being handled. Failed lists remain available for correction.
- **Useful thread and board details.** Inspect the selected URL, assigned download directory, source state and current errors. Thread details also show saved/known media and queued/active jobs. Open the folder or browser, copy the URL or remove the watch from the same panel.
- **Copy URLs for reuse.** Copy one URL or all watched thread and board URLs as a newline-separated list, ready to import again.

## Selection, board intake and combined export in the preview

Mouse/Shift/Ctrl multi-selection supports context actions, selected-URL copying,
batch removal and export. Delete removes the selection. Enter opens the actually
focused lead thread in the reader, Shift+Enter opens that thread’s gallery; these
open actions target one thread rather than the full selection. Inputs retain
native keys. Ctrl/Cmd+Shift+R opens the focused board’s Filter / exclusions wizard
from the Board list only.

Board admission uses a preview wizard by default, with literal case-insensitive
title/opening-post rules, reasons and per-thread choices. Cancelling leaves the
whole pasted batch unadded. Removed board threads are durably excluded and can be
reactivated. Editing filters changes future admission; existing watches continue.

Selected threads can share one export folder with a landing page, thread pages
and pooled verified media. Exact ordered selections identify repeat exports for
explicit update/new-folder choice, with backup protection for edits or reduced
content. Read times are per thread, not one simultaneous global snapshot. These
features are implemented in the current preview.

## Reader, navigation and zoom in the preview

The large thread reader fills the work area with readable posts and embedded
media. Up/Down moves exactly one post; Left/Right follows the frozen current
thread list/search in sort order across pages, without wrapping. A single thread
without a list scope does not acquire a global thread sequence. Text inputs keep
their normal arrow keys. These controls apply outside text inputs and embedded controls.

The app retains its header/window controls above the large reader
and gallery. Reserved preview space and retained same-thread reading anchors
reduce post jumps while media loads or the thread refreshes; failed/timed-out
previews report “The preview could not be loaded.” instead of endless Loading.

Video attachments can show persistent offline still previews made from verified
saved originals, without remote thumbnail requests. Unavailable previews keep the
original accessible through the gallery, where playback remains.

Gallery Left/Right navigates media. Zooming out stops at Fit, centers the image
and clears pan; fractional wheel/touchpad deltas give finer zoom movement.
Reader A → gallery media associated with saved post D → close returns to the
large reader at D. Without a saved association, keep the retained reader anchor.
Search/media-list origins retain their separate query/filter/page/scroll/focus
return state.

The preview includes a bounded LibVLC player: system LibVLC with plugin diagnostics
on Linux, official VideoLAN native assets on Windows/macOS. .NET self-contained
packaging remains separate. See the platform record for native video/audio coverage.
The [interface screenshots](../screenshots/README.md) document the reader,
gallery and archive scenes.

## Controls and behavior changes

**Double-click on a thread row/card opens the large reader.** Shift+Enter or its context menu opens the gallery. Double-click on a saved-media row/tile starts at that exact item; Enter does the same when that entry has focus. Board rows retain their details action. Thread details and folder opening remain separate actions. Details appear beside wide tables and overlay narrow ones; Escape closes them.

Enter in the URL field starts an import; Shift+Enter inserts a newline. Ctrl+L/Cmd+L returns to Downloads and focuses the retained field. Empty Add, the tray import action and Ctrl+V/Cmd+V outside text fields in the main window read the clipboard once. Normal paste remains available inside text fields.

Imports preserve any input edited while they run. Explicit input clears only when all entries were added or already present and the input has not changed. The result report covers the latest import; it is not a persistent activity history. Copy all includes both thread and board watches, regardless of the active tab.

The header shows transfer speed from received media bytes, with a compact history graph when the window is wide enough. Progress means **saved media / currently selected media**, with rule exclusions shown separately. The known count can grow, and 100% does not end monitoring. Queued/active counts refer to media jobs. “Archived” describes the remote thread state, not a local HTML archive.

## Upgrading from 0.8.0

Existing watched URLs, settings and assigned download paths remain usable. Back up the profile before replacing a release, and close all older applications and consumers before opening the data with 0.9.0. Fresh profiles use `%APPDATA%/.MeowChan` on Windows or `$HOME/.MeowChan` on macOS/Linux and default to `Downloads/MeowChan`. An existing installation's profile is used in place when it is the only profile; its configured or implicit media destination retains that meaning. If both profile directories exist, select one with `MEOWCHAN_PROFILE`; the older environment-variable name remains an accepted alias. Both variables may be set only if their resolved paths match. The upgrade uses new profile/media locks and a new media-manifest name. Older applications do not recognize the new locks: concurrent old/new use of one profile or media destination and downgrading migrated data are unsupported. In builds after Windows Preview 3, missing or invalid view preferences use **Barebones**; valid saved Barebones, Simple and Advanced choices are retained. Other missing appearance preferences use **Dark, English and normal density**. Published Preview 3 retains its earlier Simple default. Theme, language, view and density are saved in `settings.json`; window geometry, column layout and details-panel width are not saved across restarts.

Settings changes require a successful Save; Cancel reloads confirmed values. Both actions stay on Settings. Page navigation preserves pending edits. Theme and view changes made in the footer save immediately and synchronize only the corresponding draft field, preserving unrelated edits and validation errors. Changing the output root continues to leave existing watch destinations intact, including later threads discovered by an existing board.

English and German are included. Add or edit optional language packs while the app is closed, then restart and select the language in Settings. The [language-pack instructions](../../Desktop/Localization/README.md) describe the format. Technical provider and exception messages can remain untranslated.

The desktop now uses Avalonia 12.1.4, with matching Actipro 26.2.0 and DataGrid 12.1.2 packages. This includes the upstream fix for late Linux DBus tray registration after disposal. The library project, assembly, NuGet ID and namespaces change to `libmeowchan` and `MeowChan.*`. Consumers must update PackageReference, using directives and explicit assembly references; no binary compatibility or automatic NuGet redirect is promised. Source builds and library consumers continue to require .NET 10; self-contained desktop archives include the runtime. The new package has not been published to NuGet.

## Offline use, limits and data compatibility

The [user guide](../Help.md) leads from package extraction to an offline picture
and portable `index.html`, and explains retry, update/backup and upgrade steps.
PNG/JPEG/GIF/WebP/BMP previews depend on the installed decoder. Animation shows a
still first frame. The preview includes the bounded video player; native audio/OS coverage remains
limited to the recorded evidence. Image previews refuse files
above 64 MiB or 80 million source pixels, and bounds fit buffers to 16 million
pixels. Saved originals remain intact when a preview is unavailable.

Back up the profile **and** media directories/manifests. V1 media manifests remain
readable; V2 revision history and the archive writer's schema-1-to-2 catalog
migration are not downgrade formats. The passive current reader can read schema 1
without migrating it. New work state persists retries, source-end deadlines and
watch generations independently of post capture. A crash before the first end time
is committed cannot recover that timestamp. Disabling Save URLs on exit prevents
automatic watch restoration from retained work state as well as the URL list.

The desktop supplies the durable SQLite `WorkStateStore`. Library users must pass
it explicitly via `Registry(..., workStore: work)` under their profile lease;
`SessionStore` alone is insufficient and the default `MemoryWorkStateStore` loses
retry/end history when discarded. See the [session API](../Registry.md).

## Packages and remaining validation

The planned package targets remain Windows x64, Linux x64/Arm64 and macOS Intel/Apple Silicon. New desktop archives will use `MeowChan-<version>-<RID>` and the macOS standard is `MeowChan-<version>-osx-arm64.zip` and `MeowChan-<version>-osx-x64.zip`, containing a complete self-contained, ad-hoc-signed `MeowChan.app` without notarization. Homebrew source builds remain optional. The earlier Preview 1 exposed retained database handles, and the Preview 2 draft exposed a Windows start window exceeding the available work area. These are historical findings; Preview 3 is the currently listed preview. Published Preview 3 carries the profile-handle and startup-geometry fixes. Its Windows source-built CI job passed 628 Core and 146 Desktop tests plus native GUI checks; extracted-ZIP VLC playback, real hardware/audio and full package acceptance remain open. See [the platform record](../platform-support.md) for the exact source relation and limits. Initial macOS distribution is intentionally without Apple Developer ID or notarization; certificate acquisition is not a release prerequisite. Trusted unsigned apps can be approved individually through macOS Privacy & Security; see [macOS package guidance](../macos-signing.md). Native Mac execution and bundled VLC workflows remain unvalidated. The complete stable package matrix has not been released. Extract the whole archive and retain its native libraries, notices and documentation. Linux packages require glibc, native graphics/font dependencies including `libdbus-1` and an X11 or XWayland desktop. Published builds are listed on the [MeowChan releases page](https://github.com/tfgrass/MeowChan/releases).

Final release acceptance must identify the source commit and archive hashes and record native workflows in freshly extracted packages on the promised OS/CPU matrix. That includes download/removal/restore, clipboard/folder actions, tray fallback, shutdown, small windows and display scaling. The successful 0.8.0 CI runs remain historical evidence and do not validate this UI update. See the [platform validation record](../platform-support.md) for the current evidence and open checks.

The current branch also includes Diagnostics, basic inherited media rules, Sources and bounded/fair media admission. See the [current branch additions](../../CHANGELOG.md#additional-work-on-the-current-branch) for behavior, upgrade limits and public library APIs. Progress on this branch uses saved/selected media and shows exclusions separately. New post catalogs stay local while media may be stored on network shares. The earlier gallery and repeat-export workflow are implemented; the large reader, zoom and video controls are implemented in the current preview. The [interface screenshots](../screenshots/README.md) document the source-built reader, gallery and archive; final native acceptance of extracted packages remains open. This draft does not attest to release readiness.

Persistent pause, local search/filtering, captured quote/backlink navigation and portable single-thread HTML export are implemented. Drag-and-drop, structured import/export, TUI/daemon clients and dynamic plugin loading remain later work. Providers can already be supplied explicitly through the library contracts. Source integration is the agreed 1.0 focus; its wider scope remains a later decision.
