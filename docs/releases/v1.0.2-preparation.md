## Concrete release blockers / required preparation

### 1. Align packaged playback checks with the accepted repeat contract

Static contradiction found in [MainWindow.ApphostMediaSmoke.cs](../../Desktop/Shell/MainWindow.ApphostMediaSmoke.cs):
after enabling repeat and moving to an image, it requires `!imageCleanup.LoopEnabled`,
adds `repeat-reset-on-image`, then rejects inherited repeat on the next video.
It also requires a false LoopEnabled flag at disposal. The validator
[apphost-playback-smoke.py](../../scripts/apphost-playback-smoke.py) requires that
old check name and false loop flags in its cleanup records.

Those expectations contradict the user-approved retained preference. This is a
**statically established test-contract blocker**, not a freshly executed failing
package run. Correct the harness, verifier and affected fixtures together:

- Repeat choice survives Video→Image→Video; the next video really repeats.
- Closing, switching and shutdown still release actual native player/engine/streams,
  retain zero cleanup failures and reject late restarts. A remembered preference
  is not an active player. Do not remove cleanup assertions just to get green.
- Reopen/restart reads the chosen profile mode, but never restores Running slideshow.
- Audit other package-smoke old expectations (including media-focus teardown) on
  the exact final source. Update deliberate behavior assertions, not proven safety gates.

### 2. Validate the changed native UI, not only unchanged default routes

Current feature fixture [GalleryPlaybackFeatureChecks](../../tests/MeowChan.DesktopSmoke/GalleryPlaybackFeatureChecks.cs)
explicitly rejects Windows. The new real-input driver is Linux/XTest only.
The existing CI workflow does not explicitly invoke the opt-in MU feature/input
scenarios. Its normal tests cover settings/feedback, but cannot establish that
optional Windows video overlays and new mixed-media behavior were actually used.

Before claiming a regular cross-platform1.0.2 release, obtain dedicated Windows
input/overlay/fallback/fullscreen evidence, macOS behavior checks, and packaged
VP8/VP9/MP4 with/without audio coverage appropriate to the changed player. Use
honest native fixtures or a bounded manual record; removing an unsupported-platform
exception is not proof. Keep physical audio/GPU and the original Windows USB
performance case separate from hosted CI. Record screenshots/native inspection
without inventing visual approval (previous image-view tools were unavailable).

### 3. Check real update and profile preservation

Use isolated copies/fixtures, not a user's only profile. Cover1.0.0/1.0.1 profile
state, stored titles, pins/selected plugin candidates, enabled/disabled sources,
grants, saved mode/layout and no unsolicited slideshow. In particular compare
same-directory replacement with a new install directory; candidate-path changes
must be explained rather than silently replaced. Capture the actual Leftypol
message/phase if the user supplies it. Do not claim this incident fixed from
controlled generic startup tests.

Then require locked restores and fresh package consumers.

media manifest4 unless a separately justified change is actually needed. The
