## Stability scope to preserve

- Retained single-video loop and layout choices; explicit mixed slideshow;
  independent first/manual Autoplay; no automatic slideshow restart.
- Seek/focus/play-intent fixes, paired overlay/auto-hide, edge-only reveal and
  transient chevrons, first-key navigation, gallery shortcut context fixes,
  bindable actions without new defaults, current pause explanations.
- Reader arrow-cross overlay/end clearance, unobstructed pagination and gallery
  input, Reader return, verified callback-MP4 avformat handling and GIF fixes.
- Central acknowledgeable gallery errors without transport/auto-hide pinning;
  session repeat suppression retains diagnostics and genuine safety failures.
- Readiness-deferred preference saves and field-wise merges, local title restore
  and cleaned OP fallback, startup resume only after proven initial no-send
  admission, and correlated genuine failure history across IPC. A real HTTP/body/
  transport failure must not become a fictitious never-sent check.
- Effective transfer cap32 with stored configuration untouched, including larger
  positive values. Defaults **1 MiB/s / 5**, pending **256**, unchanged. No queue
  expansion or universal throughput/performance promise; the original reported
  Windows/Leftypol incident is not thereby proven reproduced or fixed.
- Per-session multiple High watches fairly share next whole-file slots; Normal
  gets a slot after at most three competing High reservations. No preemption,
  implicit resume or priority inheritance by replacement watches.

## Approved new selection: implementation and tests WIP

The user-facing route must be **Plugins → review → NEW selection → preview →
explicit confirmation → restart**. Only supported, unambiguous delivered-bundle
rows qualify. Confirm exact schema-valid settings; do not guess attribution from
old names/paths or silently substitute candidates. Pins, rights conflicts,
unsupported/ambiguous rows and owner conflicts remain blocked for the user's own
action. No attribution, pin, grant or ownership takeover.

Keep two backup roles distinct:

1. Immutable, hash-protected **original valid pre-v2 plugin state**, before the
   first mutation including startup. This baseline backup implementation exists;
   backup conflicts fail closed. Existing v2 state is not invented v1 history.
2. Backup of the **actual current state immediately before new selection**,
   required by the newly approved path. An old original backup is no substitute.

These are plugin-state safeguards, not a complete rollback of all profile data.
The release notes must retain full-profile backup advice and warn that old
executables cannot read the v2 plugin envelope. Downgrade uses a separate full
profile compatible with the older release, not the live upgraded profile;
subsequent changes are not automatically preserved.

Root must bind actual 1.0.0/1.0.1 upgrade results to the integrated implementation,
cover old install-directory changes, safe previews/settings, both backups,
blocked/conflicting cases and two restarts. Preserve titles, selected/disabled
sources and unrelated state; a successful backup alone does not repair the
historical 15 unavailable candidates. Do not mark this section complete on the
basis of approval, static review or the earlier baseline tests.
