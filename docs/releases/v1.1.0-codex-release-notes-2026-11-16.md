# MeowChan 1.1.0 — factual release inventory (Codex, 2026-11-16)

> **Inventory, not release approval.** This file records the user-visible and
> compatibility-relevant changes present on the integration source at the time of
> writing. It deliberately does not replace `docs/releases/v1.1.0.md`, does not
> assign a release date, and does not claim that packages are ready to publish.

## Headline change

1.1.0 is a feature release rather than a small 1.0.2 maintenance update. The
largest additions are a complete **Media** workspace, private tagging and a
**Tagging** workflow, local-file import, a read-only **Danbooru** search and
watcher source, a larger transfer/repair surface, a redesigned Reader and
work-view-based shell, and Plugin SDK 1.1.0. It also carries substantial
accessibility, keyboard, theming, settings, performance and reliability work.

## UX, shell, Reader and settings

- The workspace is regrouped into work, setup and observation areas. Downloads,
  Archive and Media are the main work views; Rules, Sources, Plugins,
  Diagnostics and Statistics are separate destinations; Settings and less-used
  commands are available through **More**. Barebones, Simple and Advanced work
  views decide which optional controls stay visible and which move into a
  labelled local More menu without removing their command, status, error or
  safety path.
- Pages and dialogs use a shared header/card/dialog language: fixed headers and
  footers, scrolling bodies, consistent Escape and focus-return rules, shared
  spacing/type tokens, named error and help surfaces, and a common menu/layout
  model. Narrow layouts move secondary tools rather than silently dropping them.
- Archive, Reader and Media use one scoped-search model. Scope chips, active
  filter chips, carry-over between related views, saved searches, filename and
  SHA-256 search, immediate source/board selection, and explanations for
  unrecognised query terms make the search state visible instead of hiding it in
  separate fields.
- The large Reader now presents posts as cards, with an opening post on the
  page, post headers, file lines, quote jumps and previews, greentext,
  spoilers, code and external-link confirmation. It supports reading position,
  “new posts” markers, last-read return, reply cards, optional conversation
  projection, post-width choices, media/sidebar preferences, post filters and
  automatic reply expansion. Reader history can remember one position per
  thread and exposes recent threads through the same context-menu vocabulary.
- Reader media supports a local inline-video path with bounded playback,
  autoplay/mute choices, one active player, local posters and a route to the
  full gallery when inline playback is unavailable. The View menu can hide
  media or show only posts with media without deleting or changing the archive.
- Settings has a searchable header, uniform rows, conditional sections, draft
  Save/Discard semantics, section/reset actions and a consolidated **Storage
  and limits** area. Many former constants are now visible, bounded settings;
  lowering a limit does not silently delete existing data.
- A Statistics page and header/tray I/O display report MeowChan's own network
  payload and media-file I/O, with retention/reset controls and separate
  network/disk directions. This is application accounting, not an operating
  system traffic monitor.
- The shell has a MeowChan title bar and tagline, profile/window handling,
  update notices with Release notes/Later/Skip this version, a rolling
  per-user log, visible recovery from unexpected UI-thread errors, and a
  system-title-bar escape hatch (`MEOWCHAN_WINDOW_CHROME=system`).
- Light and dark palettes, theme-aware cat branding, focus rings, selected
  shapes/bars, contrast-pinned palette values, reduced-motion/Animations
  settings, shared popup geometry and icon-based controls establish a common
  design language. Screen-reader names were added to pages, dialogs, facts,
  tiles, spoilers, controls and status messages.
- Keyboard defaults were reorganised around the footer and current work-view
  order. Media/thread tags, filtering, Reader find, gallery playback,
  selection, export, folder opening, favourites, rating and back-navigation
  commands have explicit bindings; saved user bindings remain authoritative.
  macOS uses platform-appropriate modifier and glyph presentation. Shortcut
  help is binding-driven rather than a second hard-coded command list.
- English and German remain the primary maintained languages. Ten additional
  language packs (Spanish, French, Russian, Simplified Chinese, Japanese,
  Korean, Brazilian Portuguese, Czech, Italian and Polish) contain reviewed
  text/plural/terminology changes but are still marked **Untested** pending
  native-speaker and rendered-UI review.

## Gallery, playback and viewing

- The gallery toolbar was rebuilt around a stable left/centre/right layout. Back,
  navigation, position, Fit, 1:1, post panel, favourite and playback remain
  discoverable; less frequent zoom, export, rating, tags, slideshow options,
  overlays, fullscreen and shortcut help use a labelled overflow menu on narrow
  layouts.
- Gallery playback distinguishes Manual, Repeat-current-video and Slideshow.
  Slideshow starts explicitly, keeps video looping independent from navigation,
  honours pause/hold conditions, and exposes duration and playback settings.
  Video controls include seek, volume, speed, frame stepping, A–B looping,
  zoom/pan and rotation without modifying the original file.
- The filmstrip is virtualised and can show type, duration, GIF, favourite,
  rating and missing-tag badges. It receives persisted video duration and
  follows the revised gallery shortcut scheme. Edge controls, auto-hide,
  overlays, focus, native popup targets and transitions were hardened during
  the integration pass.
- Gallery and Reader can show verified local video posters. Images use a
  bounded decoded-image cache and configurable neighbour preloading; cache
  entries are tied to full file identity rather than only size and timestamp.
  Archive, Reader and Media previews share the relevant cache paths.
- Gallery/file actions now consistently offer Original export, Show in folder,
  Open with default program (with runnable-file safeguards), Copy file path,
  tags, ratings and the appropriate context menu. The gallery can return to the
  exact Media view or thread context that opened it.
- Native media lifecycle, overlay-window, popup-root, focus and playback
  transitions received platform-specific hardening. These changes improve the
  source-level lifecycle but do not by themselves constitute Windows/macOS
  native acceptance.

## Media workspace

- **Media** indexes saved media across archived threads in a tile grid and can
  sort by thread, capture time, filename, size, references, tag count, rating
  or random order. Missing/unavailable media are represented explicitly.
- Filters cover tags, media type, favourites, rating, source, board, filename,
  thread and video sound state. Active filters remain visible as removable
  chips; focus mode provides a grid-first view without losing the query or
  result count. Free-text search can report the field where a match occurred.
- Identical bytes are grouped by SHA-256 with occurrence counts and per-thread
  details. Grouping does not merge occurrence-specific tags or metadata.
  Tiles show type/provider/saved/tag/favourite/rating state with stable badge
  placement, verified local posters and a shared selection model.
- Ctrl/Cmd-click, Shift-click, keyboard range selection and Select all support
  batch tagging, gallery opening and original export. The Media page has a
  configurable selected-media sidebar with previous/next navigation, video
  controls and a Layout menu; it can be hidden at narrow widths without
  discarding the saved preference.
- The same media actions and context-menu vocabulary are wired through the
  Media page, Archive table/tiles, Reader attachments, gallery and video
  overlay. The selected item, right-clicked item and multi-selection semantics
  are kept distinct.
- Read-only folder sources can index external image/video folders without
  moving, renaming or writing the source files. Folder metadata is kept in the
  profile, full hashes are obtained lazily/boundedly, and changed file versions
  do not silently inherit tags.

## Tagging and curation

- Private own tags are profile data, separate from provider tags and thread
  tags. Threads can be tagged from Archive and Reader; exact media versions can
  be tagged from Gallery, Media, Reader attachments and Archive media. Tag
  filters support include/exclude and all/any semantics; Tag manager supports
  counts, rename, merge, deletion and recovery-aware cleanup.
- The tag editor uses one searchable list with use counts, assigned tags first,
  sorting choices and one-step undo. Multi-file editing reports all/some/none
  state (for example “3 of 5”). Tag pills distinguish own, thread and provider
  tags by shape/marking as well as colour.
- Gallery quick tagging and anchored tag popovers reuse the same suggestions,
  stamp and undo model. Suggestions can come from the current thread, nearby
  media, filenames/titles, recent use and provider source tags; provider tags
  remain suggestions for own tags and are never silently treated as local tags.
- The Tagging page provides a queue, saved stamp, ordering, selection/grid
  views, progress, group support, walk mode and optional decision cards.
  Enter/Space/Backspace, stamp actions, card keys, queue marks and bounded
  undo history are exposed through the normal command/shortcut system.
- Own tags can protect threads/media from cleanup, follow a same-byte
  attachment-key recheck, and remain visible as orphaned assignments when a
  file is missing or replaced. Loose/legacy occurrences are taggable only when
  MeowChan has an inventory identity (captured occurrence, own import or
  registered folder-source version); arbitrary filesystem files are not
  silently enrolled.
- Own tags are intentionally not included in transfer packages or original
  exports. Danbooru media has provider-tag provenance, but own-tag controls are
  disabled there in this release.

## Import, transfer and export

- **Import files…** accepts files, folders and optional subfolders/drop input.
  It hashes and classifies the selection before copying, reports duplicates,
  unsupported/unreadable/oversized files and skipped links, and never moves or
  changes the user's originals. New files are copied into `meowchan-import/`,
  receive an optional batch name/tags, and appear in Media, Gallery and
  favourites. Limits and partial-stop behaviour are explicit.
- **Inspect transfer package…** verifies and stages a package before any archive
  write, plans a new thread or merge, shows the decision, and applies only on
  explicit confirmation. A multi-thread set is applied sequentially with an
  honest partial receipt; replay is idempotent. Private-metadata packages are
  refused rather than partially imported. **Check again** rereads a package
  changed on disk.
- Media merge conflicts are recorded by slot/bytes and can be reviewed through
  Manage conflicts: keep, discard or promote an alternative, with confirmation.
  Discarded unreferenced roots can be reclaimed. Interrupted import/merge state
  is presented at startup for an explicit two-step discard decision instead of
  being silently deleted.
- One export dialog covers HTML/link-list selection and scope. HTML follows the
  Reader card presentation, supports System/Light/Dark without scripts or
  external loads, includes the known thread facts and credits, and uses the
  export-start language snapshot. URL-text export and archive/original export
  paths are also available. Original export reports unavailable items rather
  than silently omitting them.
- The 1.0.2 upgrade path includes transactional archive schema migration,
  journal pruning with a checked backup, new first-use profile files for tags,
  imports, Booru, statistics, folder sources and queues, and explicit backup
  handling. A complete profile/media backup is required before upgrading;
  1.0.2 cannot be used as a supported downgrade target for an upgraded profile.

## Booru, sources and plugins

- MeowChan includes a bundled, read-only **Danbooru** post-search source. It
  supports tag queries, single-post lookup, bounded preview fetching, result
  cards, provider ratings/score/favourites/source tags, canonical links and
  local provenance. It does not upload, vote, edit provider tags, use accounts
  or silently fetch originals from a preview.
- Danbooru watchers can be saved, paused, checked now, resumed, removed and
  caught up using a post-id cursor. Baselines, cooldown/Retry-After bounds,
  provider/session pause, profile-maintenance fences, restart recovery,
  cancellation/retry and watcher notifications are represented explicitly.
  Requested originals enter the ordinary download queue and saved provenance
  appears in Media/Gallery/Favourites.
- `booru-catalog.json` stores provider posts, findings, watcher state and local
  links separately from own tags. It is size/schema/duplicate checked and fails
  closed on malformed or future data. The catalog limit is configurable.
- Sources and Plugins share a redesigned two-level page but remain separate
  concepts. Source cards expose maturity/maintenance/status, watches and
  integrity/permission controls; plugin details expose activation, repair,
  consent and SDK state. Add plugin copies a `.cs` source without overwriting or
  running it, with build/activation deferred to the documented next step.
- Read-only external folder sources and profile windows are additional source
  management features. The source/plugin startup path can reuse verified
  unchanged descriptions, verifies toolchain inputs close to use, and keeps
  changed declarations/permissions explicit.
- Plugin SDK 1.1.0 adds typed Booru post-search contracts, cursor semantics and
  `PluginDeclarationStatus`. The public API inventory moved these declarations
  to Shipped. Hosts accept SDK declarations `1.0.0` and `1.1.0`, but a plugin
  using post search requires 1.1.0. The SDK remains explicitly non-stable in
  1.x.
- Five further experimental chan sources are bundled disabled by default;
  two more are documented technical blocks without a route/network path.
  Engine-family handling and several 2ch/7chan/Uboachan attachment/source
  corrections improve parsing and integrity decisions. No live availability is
  implied.

## Platform, reliability and compatibility inventory

- The repository contains packaging and validation paths for Windows, Linux
  x64/ARM and macOS ARM/Intel, plus native-display, plugin, upgrade and
  release-gate checks. The source includes platform-specific title-bar,
  modifier, menu, playback, packaging and signed-payload handling.
- Startup and persistence are more defensive: reads can proceed while the
  session starts, writes wait for admission/readiness, failed download loops
  restart on a later signal, unreadable journal rows no longer hide all
  watches, damaged backups are isolated rather than overwritten, and profile
  recovery reports the next action.
- The application now records richer network-stage/failure evidence, uses
  bounded queues/caches, avoids unnecessary manifest/plugin/index work, and
  protects profile writers with explicit admission. These are reliability and
  observability improvements, not a universal performance guarantee.
- The public API review found additive SDK/Core surfaces as well as two
  compatibility cautions: the SDK contract version changes to 1.1.0, and a
  profile-bound Core consumer must use `Registry.StartAsync(lease)` before
  restore/mutation; the old `RestoreAsync()`-first lifecycle is intentionally
  refused. Do not advertise 1.1.0 as a blanket binary-compatibility release.
- The archive schema and profile files change as described above. A 1.0.2
  executable should not be pointed at a profile after the 1.1.0 migration;
  restore a complete pre-upgrade backup for a rollback.

## Verification status and release caveats

The inventory is source/history-based. It is not a substitute for release
acceptance, and this commit intentionally does not alter the product or the
existing release-note drafts.

At the time of writing, the GitHub validation run
`43778166862` was still **in progress** for the exact compared source
`42e7afb0b`. Therefore the following claims are **not yet safe to advertise**:

- “1.1.0 is released”, a release date, a public download, a stable tag, or
  release-ready executables;
- “all validation is green”, “all platforms passed”, or an accepted
  `stable-candidate all/all` run with its complete package inventory and
  checksums;
- successful final packaged-apphost upgrade evidence from the exact release
  source, including the 1.0.2 fixture and offline restarts;
- Windows/macOS native acceptance for title bars, menus, keyboard/focus,
  scaling, screen readers, hardware audio/GPU or physical speaker output;
- live Danbooru availability, rate behaviour, or provider compatibility;
- live verification of any experimental chan source;
- native-speaker approval of the ten preview language packs, rendered
  whole-application contrast, or a blanket performance claim;
- blanket source/binary compatibility for existing Core consumers or plugins.

The safe wording for now is: **“The 1.1.0 integration source contains the
following implemented feature set; final release validation and publication
are pending.”** Historical focused tests and earlier CI runs remain evidence
for their own source SHA and scope; they must not be combined into a final
release PASS. The release should be advertised only after one exact-source
candidate run, package/source/checksum verification, the required upgrade
fixture and the maintainer's platform/native checks are recorded.
