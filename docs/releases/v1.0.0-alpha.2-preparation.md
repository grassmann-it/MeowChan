# Preparing 1.0.0-alpha.2

Local candidate preparation only. No push, tag, remote workflow dispatch, upload
or publication is authorized by this preparation. Keep the existing alpha.1 tag
and stable 0.9.0 release unchanged. Public draft text: [alpha.2 notes](v1.0.0-alpha.2.md).

## Candidate binding

Freeze the integrated working copy after the version, package/CI, reader and
accessibility corrections. Record commit, complete WIP/source hashes, build
commands, package inventories and SHA-256 hashes. Build and runtime evidence must
point to that same source boundary. Prior 0.9.0 or earlier 1.0 checks do not become
alpha.2 checks by renaming an archive.

Use `Version=1.0.0-alpha.2` consistently for product/package metadata, sample
package references and normal/RID lock graphs. Keep `SdkContract.Version=1.0.0`.
macOS numeric bundle fields remain numeric while product metadata and filenames
retain the full prerelease version. Check each shipped helper apphost and all
compiler/reference/plugin payloads, not only the desktop executable.

## Local checks

Serialize .NET, publish and GUI operations under
`/tmp/meowchan-ui-1.0-build.lock`. Use a fresh output directory and isolated
profiles/media; Linux GUI runs use private Xvfb/DBus. Record these separately:

| Check | Required evidence |
| --- | --- |
| Integrated tests and targeted reader/accessibility regressions | Exact source/runtime hashes and actual test outcomes, including skips |
| Real old-profile migration | Fresh profile from the pinned [0.9 generator](../../tests/fixtures/upgrade-v09/README.md), delivered PluginSession startup and two offline restarts |
| SDK-free packaged source/filter workflow | Actual archive/extracted apphost, no SDK/NuGet/network access, read-only relocated install, source/filter workers, download, durable archive, offline restart and shutdown |
| Package matrix | Per-RID inventory, helper identity, compiler/references, native video and legal/source companions; separate native execution from crosspublish |
| Native user checks | Exact package/version, platform, scaling, fresh/upgrade profile, steps, outcomes and limitations |

The maintained Linux package probe is
`scripts/apphost-plugin-workflow-smoke.py`; its `--archive`, `--archive-root` and
`--archive-member` must describe the actual package. Its `--source-commit` is a
full commit SHA; retain the WIP/source manifest alongside the result when the
candidate includes uncommitted changes. It runs the real PluginSession with
terminal HTTP fixtures, not a live provider or an injected-provider substitute.
Do not increase its timeout or skip assertions to hide a failure.

Native Windows follow-up: [short recipe](v1.0.0-alpha.2-windows-check.md).
Apple Silicon 0.9.0 user feedback covers start after manual exception, tray and
shortcuts only. Windows remains pending. Neither is alpha.2 native acceptance.

The offline inventory/assembly entry point is `scripts/assemble-prerelease.py`.
It consumes retained artifacts of one successful `prerelease-candidate` workflow
run, with explicit `--source-commit`, `--version 1.0.0-alpha.2`, `--run-id`, the
pinned 0.9 video-source base (`--source-base`) and a fresh `--output` directory.
It writes the reviewed assets, `candidate-inventory.json` and `SHA256SUMS` after
identity/provenance checks. `prerelease-candidate` is a workflow_dispatch mode in
`dotnet-desktop.yml` with `platform=all`, `scenario=all`; it is not a publication.
No current run is implied here, and this preparation authorizes no dispatch.

## Release handoff after separate authorization

Review final release text against actual results and remaining defects. Require
an explicit reviewed alpha inventory that binds binaries, source companions,
checksums and originating validation runs to alpha.2. The stable 0.9.0 assembler
and upload path must keep their accepted inputs and version guards.

Any later alpha release must be a prerelease with `make_latest=false`; verify
latest still resolves to v0.9.0. Attach only the actual validated assets. Replace
provisional source links with the chosen commit/tag, and keep incomplete native
checks visible. Prerelease update checking remains the user's explicit opt-in.
