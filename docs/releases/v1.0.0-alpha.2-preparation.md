# Preparing 1.0.0-alpha.2

On 2026-10-25 the maintainer authorized publishing `1.0.0-alpha.2` as the
replacement preview for alpha.1, including current-source GitHub Actions packages
for testing. Stable Latest stays at `v0.9.0`; retain the alpha.1 tag and history.
Publication requires the matching successful full-matrix candidate run and its
verified inventory. Public release text: [alpha.2 notes](v1.0.0-alpha.2.md).

The release preparation corrects the now-removed preview.3 source-base URL to
the byte-identical numbered source asset in v0.9.0. It also integrates the
previously prepared narrow AppImage PluginWorker observer classification and
updates the existing real-process test to pass its required observation deadline.
The 28 Linux distribution/worker tests and 39 candidate assembly tests pass
locally; actual package results must come from the new Actions run.

## Scope expanded before publication: sources, filters and video controls

The maintainer explicitly includes NW-00–07 and FE-01–05 in the still unpublished
Alpha 2, and requests a single round video Play/Pause button, volume/mute and
looping instead of simultaneous Play/Pause/Stop buttons. The version remains
`1.0.0-alpha.2`. The baseline-only full candidate `40213401965` on `1194207`
was cancelled because its inventory no longer represents the requested release.
It is not a failed acceptance result for the later wave and must not be published.

The expanded delivery is 16 plugins, 11 sources and 14 editable C# examples.
Five new sources are default-off/Experimental. Four use activation with strict
integrity; Leftypol joins the three existing explicit provider-size/MD5 exceptions.
SHA-1 is strict and size hints are preserved separately. Four new local filters
join image dimensions; one filter per effective rule remains the current model.
Archive SQL schema 5 and media manifest 4 require actual migration/regression
checks. The broad wave run found real historical raw-MD5 read incompatibilities
in rule decisions and work state. Those are corrected on `9894847`, with two
pre-fix WorkState failures and 44 post-fix Core tests retained as separate evidence.

Root merged the verified baseline through `1194207` and the compatibility fixes
into integration `4a0ca79`, which also includes the new bounded five-source live
harness. The next full regression runs on that clean source; pending video and
additional GUI/process-restart checks have not yet been accepted. Earlier source
replay, package-consumer and GUI results keep their original source bindings.
The final full native candidate and its package inventory must contain the entire
expanded scope. No Alpha 2 tag or release has been published.

## Native findings addressed before the next candidate

Windows exposed actual historical `TimeZoneInfo` differences (Sao Paulo's gap
and Apia's skipped day). Calendar execution now uses pinned NodaTime 3.3.6 with
bundled IANA TZDB on all platforms; persisted query IDs and public APIs stay the
same. All affected lock graphs include the dependency; its exact upstream
license/notice and NuGet identity are included in THIRD-PARTY-NOTICES.md.

Worker termination now gives the Windows kernel a bounded 500 ms cleanup phase
after the owned tree has exited, before returning from disposal. It retries only
the exact owned workspace, without relaxing process/job identity or exit checks.
The direct SQLite fixture connections disable pooling so Windows can remove
their disposable database after close; production database handling is unchanged.

The first Linux ARM64 AppImage probe caught a *pre-exec* child and incorrectly
authenticated the inherited parent image as a second main apphost. The observer
now records that inherited fork snapshot separately after checking its live,
authenticated parent. It does not stop or count the child as a main process.
Already authenticated main-process identity/image changes still fail, and the
actual workflow PID-set/full-payload/count assertions are unchanged. This
supersedes the earlier narrow mid-exec-only helper classification; it is not a
claim of independent executable-descriptor proof for every helper process.

Focused Windows run `40195979755` at `3ea020d` passes all ten offline test
assemblies (2109 passed, five explicit opt-in skips), package fixtures and plugin
delivery verification. This confirms the timezone and worker-cleanup corrections
on the hosted Windows runner. It then fails the GUI bookmark-to-gallery test:
its synthetic manifest predates explicit attachment bindings. The bookmark,
reader and mixed-reader fixtures now prepare exact strict revision receipts for
their controlled saved images and verify those associations before UI testing.
Image display, cursor navigation and exact reader-return assertions remain
unchanged. This is fixture preparation, not production acquisition evidence.
The failed focused run is retained, and is not a release acceptance run.
