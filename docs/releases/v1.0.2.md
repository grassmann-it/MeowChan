# MeowChan 1.0.2: stability and reliable viewing

This regular stability release focuses on dependable startup, downloads and media interaction.

## “Goon Central” for /gif/ power users

Download a thread and browse its images, WebM and MP4 directly in the gallery—with
remembered looping, media focus and mixed slideshow. Less “open the download folder,
find the files, launch VLC”: the viewer replaces that round trip, not every VLC feature.

## Viewing and interaction fixes

- **Remember your viewing choices.** Single-video repeat, media focus and layout
  choices survive profile restart. Manual, Repeat and mixed Slideshow keep video
  looping separate from automatic navigation. Slideshow starts explicitly; a
  saved mode does not restart it automatically. Images use their display period,
  while videos advance at their actual end.
- **Predictable autoplay and controls.** First/manual video playback follows
  Autoplay independently of saved Slideshow mode, without silently starting
  automatic next. Seeking, volume and panel interaction preserve native
  play/pause intent. Seek and video-to-image focus handling are more reliable.
- **Reachable overlays and shortcuts.** Overlay and auto-hide are paired. Bottom
  and right edge hover reveal controls and post context; center motion does not
  reopen panels. Brief, borderless motion-triggered chevrons indicate the edges.
  Interaction and keyboard focus keep controls reachable, with docked fallback
  where native transparency is unsupported. The first navigation key works even
  with hidden controls. Gallery Left/Right navigates media from the timeline or
  volume control; Up/Down adjusts available video volume. Protected text, dialog
  and other native contexts retain their behavior. Additional gallery actions
  are bindable without adding default shortcut collisions.
- **Safer native windows.** Windows overlay clipping avoids redundant clip/focus-
  adorner layout feedback; terminal control retirement and late-pointer guards
  protect stop/close transitions. Video-to-image and Reader transitions hide the
  separate video overlay so an empty window cannot block slideshow progress.
  This does not repair framework subscription retention generally. macOS rapid-fullscreen restoration preserves observed
  entry frames against delayed native callbacks while respecting new user resizes.
- **Read without losing space.** The Reader arrow cross overlays narrow layouts
  instead of reserving a bottom strip. End clearance keeps the last post
  reachable, and Reader pagination adorners no longer intercept gallery clicks.
  Reading post context pauses automatic navigation until explicitly restarted,
  not the video itself. Reader/gallery return and verified MP4-stream handling
  have also been corrected.
- **Clearer errors, fewer interruptions.** Technical gallery errors use central,
  acknowledgeable feedback rather than an extra gallery banner or a transport/
  auto-hide pin. Dismissing matching banners/toasts suppresses session repeats
  without deleting diagnostics; passive expiry is not acknowledgement. Real
  integrity, codec and cleanup failures still fail closed.

## Startup, titles and downloads

- Display-preference saves wait for session readiness instead of failing during
  startup; field-wise merges preserve newer changes such as volume edits.
- Known local thread titles return after restart. Missing display titles can use
  a cleaned opening-post excerpt without inventing source metadata.
- Startup checks can resume after a proven initial admission that sent no request.
  Genuine HTTP, body and transport failures retain their history and remain
  visible; ordinary poll/minimum intervals are preserved. Plugin diagnostics
  identify the failing startup phase more precisely.
- Effective simultaneous transfers are capped at **32**, without rewriting your
  stored concurrency setting. Defaults remain **1 MiB/s and 5 transfers**; the
  pending queue remains **256**. This is a bounded stability fix, not a universal
  performance or Internet-throughput promise.
- Multiple **High** watches share fair next whole-file slots for the current
  session. Under contention, Normal receives a slot after at most three High
  reservations. Priority does not interrupt an active file, resume a paused watch
  or transfer to a replacement watch.

## Updating older plugin selections

An explicit **new selection of currently delivered bundled plugins** can resolve
missing old candidates without claiming that their former origin was recovered.
It is a confirmed new choice, not a silent name/path mapping.

After updating, open **Plugins**, review the affected entries, choose **NEW
selection**, inspect the preview and explicitly confirm only supported,
unambiguous rows and their exact schema-valid settings, then restart. There is no silent
name/path fallback. Pinned entries, rights conflicts and ambiguous or
unsupported rows still need your own action; the process does not take over
attribution, pins, grants or ownership.

The original valid pre-v2 plugin state is backed up immutably before its first
mutation. The new selection also requires a backup of the **actual current state
before the first confirmed new selection (retained, not refreshed for later rows)**; an original pre-v2 backup is not that snapshot,
and an existing v2 profile must not be presented as invented v1 history.

**Back up your entire profile before upgrading.** Plugin-state snapshots are not
full-profile backups. Older versions cannot read the v2 plugin envelope: do not
point an older executable at the upgraded profile and assume downgrade safety.
Use a separate full-profile backup made for that older version when reverting;
changes since that backup will not automatically be retained.

## Release process and evidence

Release assets require **one exact-source `stable-candidate` run with `all/all`,
all 13 required jobs successful and all 18 original assets**, followed by root
verification of source identity, upgrade/package evidence, inventory and checksums.
Focused native checks, local test counts and assets from older runs cannot be
combined into that acceptance. The published release will identify its accepted
run, source commit and checksums.

The release documentation is part of that frozen source: integration requires a new full exact-source candidate before publication.
This document does not attest that a running candidate passed or that publication
has occurred. Final public run/source/checksum references belong to the release
record after the gate succeeds, not to an earlier source checkpoint.

Native playback checks distinguish decoded audio without an output from functional
native output; neither establishes audible physical-speaker output or every GPU,
audio device and desktop environment. The manual Windows field test is explicitly
scheduled **after publication**, without waiving technical pre-publication gates.
Follow-up fixes may use 1.0.3. No new sources or unselected CSV extras are included.
See [release preparation](v1.0.2-preparation.md).
