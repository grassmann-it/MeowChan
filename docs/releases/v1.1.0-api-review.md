## Signaturen, Gleichheit und bewusste Folgen

- Alle neuen Records sind `sealed` und positional; Listen sind
  `IReadOnlyList<T>` ohne defensive Kopie, wie die Shipped Source-DTOs. Sie
  sind Transport-DTOs über den Workerprotokollrand, keine Hostautorität.
- Ein späterer zusätzlicher Recordparameter oder ein neues Interface-Member ist
  ein Binär-/Implementiererbruch. Das ist mit dem nicht-stabilen 1.x-SDK
  vereinbar; eine solche Änderung braucht eine neue SDK-Version und ein eigenes
  Review. Position und Default von `BeforePostId` / `NextBeforePostId` sind mit
  dieser Freigabe für 1.1.x festgelegt.
- `PostOrderKind.DecimalPostId` (bereits Shipped) bekommt für PostSearch-Quellen
  eine zusätzliche dokumentierte Bedeutung (positive Dezimal-IDs, streng
  absteigende Seiten, Cursorunterstützung). Signatur unverändert, daher keine
  Inventarzeile. Die neue Validation in `40f1311b` greift nur in Booru-Pfaden;
  Thread-/Catalogvalidierung ist unverändert.
- Keine Core-Typen im SDK; kein Credential-, Cookie- oder Downloadvertrag.
