# MeowChan 1.0.0 — release text template

**UNRELEASED TEMPLATE — native acceptance and the stable freeze are open.**
This file announces no downloads. Replace this banner only after the stable

[preparation handoff](v1.0.0-preparation.md).

MeowChan 1.0 introduces the Semi + Ursa interface for downloads, local reading,
the gallery, archive search and settings. Consistent spacing and state indicators
make download errors, settings drafts and archive filters easier to follow while
keeping the familiar appearance. Gallery tools sit below the media; video
transport and plugin, collection, export and cleanup dialogs follow the same
interface roles. Sources and image filters are supplied
as plugins, with an overview for enablement, revisions and access decisions.
The packaged compiler and worker support explicitly selected local C# source
files without requiring an end-user .NET SDK.

The supplied sources are 4chan, 8kun, Lainchan, Kohlchan, Wizchan and Endchan.
Kohlchan, Wizchan and Endchan are Experimental and start disabled on their first
registration in a profile; existing saved activation and permission choices stay
intact. Submitting a matching URL for a disabled source offers **Activate and
allow differences** (**Aktivieren und Abweichungen erlauben**). This explicitly
activates the source and allows provider size/MD5 differences for that profile,
plugin owner and source. The two saves are separate: existing watches may resume
after activation; the new URLs wait for both steps to succeed. On a partial
failure, review the saved state and retry explicitly; closing does not undo
activation. Sources remains the place to manage or revoke permission. Manual
enablement and later URLs for an active source grant no new exception. Mismatch
permission is off by default, and earlier failures need a separate manual retry.
Provider SHA256, local verification, transfer completeness,
limits, filters and cancellation remain enforced. Revocation blocks new
acceptance requiring permission; verified older archive media remains readable.
Automatic settings-backup recovery disables recovered permissions pending explicit
regrant. Source availability is not guaranteed.

Archive cleanup previews eligible threads and requires deliberate confirmation
before permanent local deletion. Favorites and other protected/in-use entries
remain excluded; unknown storage is not treated as empty. Review the losses
and back up before deleting.

Back up the whole profile and media before upgrading from 0.9.0, and retain exports
separately. Close older writers first. A profile modified by 1.0 has no promised
downgrade path; use the untouched backup to return to 0.9.0. Trying an isolated
test profile first remains useful.

The Library, PluginSdk and optional PluginHost package version will be `1.0.0`;
the independent SDK protocol contract remains `1.0.0`. Their public APIs are
reviewed for this release; future 1.x API stability follows the documented package
contract. Custom library providers must explicitly bind new attachment revisions
to committed acquisitions; matching metadata alone no longer creates the old
implicit association. See the [migration note](../../CHANGELOG.md#breaking-librarysdk). Local plugins run
with user permissions; worker separation is not an OS sandbox.

macOS delivery remains ad-hoc signed without Developer ID/notarization unless
the final candidate explicitly proves a different signing state. Follow the
[first-launch guidance](../macos-signing.md). Keep any final limitations here;
the open [native matrix](v1.0.0-native-checks.md) must not disappear by changing
the product version.
