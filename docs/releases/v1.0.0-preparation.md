## Existing candidate assembly and assets

Keep the retained `scripts/assemble-stable-release.py` and
`.github/workflows/upload-verified-release.yml` **0.9.0 contracts unchanged**.
The 1.x stable path is already `scripts/assemble-prerelease.py --channel stable`;
its default channel still rejects stable versions. Stable mode rejects suffixes
and requires the exact version in committed source. No second pipeline is needed.

The existing `stable-candidate` workflow mode requires all five native platforms,
all scenarios, the three developer packages, API release review, legal/source
checks and one successful run. The later separately authorized operator must
verify that all inputs originate from that same successful run and source;
`--run-id` merely records a number and does not query Actions. A local Linux-only
candidate cannot be assembled as the full stable set. There is no run ID for
this handoff and no remote command is executed or authorized here.

```sh

(cd "$MC_FRESH_STABLE_STAGE" && sha256sum --check --strict SHA256SUMS)
```
