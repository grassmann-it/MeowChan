# MeowChan 1.1.0: Media page, own tags, Danbooru and plugin SDK 1.1.0

> **Draft / unreleased.** MeowChan 1.1.0 is not published. There is no release date,
> no tag, no downloadable package, no accepted candidate run and no package
> verification. This page is a working draft of the release notes. Statements describe
> the source as it is documented and tested at the base named in
> [Basis of this draft](#basis-of-this-draft); items that are not yet integrated or
> not yet verified are marked **Pending**. The final text will be written at
> publication.

This is a feature release on top of [1.0.2](v1.0.2.md). It adds a Media page over
everything you saved, own tags, an import for your own files, a first Danbooru source
with watchers, a larger set of bundled experimental chan sources and plugin SDK 1.1.0.
The Reader shows posts as cards, every window gets MeowChan's own title bar, the
keyboard shortcuts are reworked, a new **Animations** setting controls motion, a found
update is announced with a quiet notice, and most amount and size limits are now
settings. Several profile files change or are added on first start. There was no 1.0.3
release; its preparation work is part of 1.1.0. Read
[Upgrading from 1.0.2](#upgrading-from-102) before you replace an existing
installation.

## Media page and own tags

- **A Media page for everything you saved.** A **Media** button next to Archive shows
  every saved media file across all archived threads as a tile grid, sorted by thread
  (default), newest or random. Filter by tags, type, favorites, rating, source, board,
  file name, thread and, for videos, whether they have sound. Saved files that are
  missing can be shown. Tiles show your favorite mark, rating and own tags and the
  local video poster, and tags can be edited on the tile. Tiles show their state in
  fixed corners (type, provider, not saved, **No media tags yet**, a favorite star on
  hover or focus); a grouped tile shows the favorite state of its occurrences. The page
  opens the shown files as a gallery and jumps to the post in its thread. From the
  gallery, **To media** returns to the page; from the thread, **Back to media**
  (Alt+Left) returns to the same view with its filters, order, selection and scroll
  position. The page reads a derived index that loads in the background with a status
  instead of freezing the window; the index cache is disposable and rebuilt when
  damaged or when its version changes.
- **Active filters stay visible.** Every active Media page filter shows as a removable
  chip under the toolbar, also while the filter area is closed, with **Reset all** and a
  count on the button ("Filters (3)"). **Without media tags** and a clickable
  "N without media tags" count give you a place to start tagging.
- **Duplicates are grouped, not merged.** Files with the same SHA-256 appear once with
  an "in N threads" hint that lists every occurrence (source, board, thread, file name,
  own tags, **Show in thread**). Tags stay with each occurrence and are never copied
  between them.
- **Select, tag and export from the page.** Ctrl/Cmd+click, Shift+click and Ctrl/Cmd+A
  select tiles. A selection can be tagged together in one all-or-nothing write, opened
  as a gallery or exported as originals. **Export all matches…** exports one original per
  shown tile through the existing export dialog and asks first above 500 files or
  2 GiB (both are settings). Tiles that are unsaved or have no original are counted as
  unavailable, not skipped silently.
- **Several files in a thread's media tab.** A thread's media tab selects like the
  Media page: Ctrl/Cmd+click, Shift+click, Shift+arrows, Ctrl/Cmd+A and Esc. With two
  or more files selected, **Tag together…**, **Selection as gallery**, **Export
  originals…** and **Clear selection** act on all of them, also from the right-click
  menu; every other command still acts on the file you clicked.
- **Own tags.** Tags are private to your profile and stored in `private-tags.json`.
  Tag a thread from the Reader (tag bar with `/name/` suggestions taken from the title
  and first post) or with **Tags…** in the Archive thread menu, and tag the exact shown
  media version from the gallery. Your own tags are suggested while you type. Threads
  show their tags in the thread list and table. The Archive filter can include or
  exclude tags (all or at least one included), saved searches describe tag filters by
  name, and the **Tag manager** lists thread and media counts, renames tags and deletes
  them after a question that names both counts. Thread and media tags do not inherit
  from each other.
- **Tag dialogs built around search.** One field filters a single list of toggle rows
  with use counts: the tags on the file first, then the most used, then A to Z (or sort
  by most used), with one-step undo from the footer. Tagging several files together
  shows for each tag whether all, some or none of them carry it ("3 of 5"). The Tag
  manager offers the same sort choice.
- **One chip look.** Own tags are filled, thread tags carry a house mark and Danbooru
  source tags have a dashed outline and a category mark, so they differ by shape and not
  only by colour.
- **Tags protect what they mark.** A thread with an own tag, or with a tagged media
  version, is protected from archive cleanup. Permanently deleting a thread removes
  its tag assignments and reports a failed cleanup instead of hiding it.
- **Tags follow a re-check.** When a source changes what it reports about an attachment,
  tags on the old attachment key are handed over to the new key for the same
  attachment and the same bytes. Different bytes do not inherit tags.

- **Loose and legacy files can be tagged.** Saved files that are not bound to a
  captured post (not assigned, or only matched to a post through the old metadata
  comparison) are taggable from the gallery, the Archive menu, the Media page and
  batch tagging, through one shared target resolver. Each such file has its own
  occurrence identity (thread, media folder and requested file name) with a revision
  per published asset; the bytes, hash and path locate the file but are not its
  identity. The same bytes in two places are two occurrences. New bytes in the same
  place are a new revision that does not inherit tags. Tags of a bound view are never
  copied to a loose view or back. Every add checks the file again and hashes it
  completely, which takes noticeable time for large videos.
- **Missing or replaced files keep their tags as orphans.** A file that is missing,
  moved, replaced or has since become bound keeps its assignments, still counted and
  removable. **Check tagged loose files** in the Tag manager lists them and removes
  exactly the checked assignments; unreadable evidence is counted as "not checkable",
  never as an orphan. Permanently deleting a thread removes its thread, bound and loose
  assignments and its loose registrations but keeps the tag definitions; a failed cleanup
  is reported and can be repeated with **Retry tag cleanup** in the delete dialog.
- **Own tags are not exported.** Transfer packages and original exports carry no own
  tags; the Export originals dialog says so before the export.

- **One media context menu everywhere.** The Media page, Archive table, tiles and inline
  attachments, the gallery and the video overlay share one right-click menu with the same
  order, labels and reasons; it acts on the right-clicked item (also with Shift+F10 and the
  Menu key), and the gallery menu now offers own tags and **Copy file path**. A disabled
  entry explains itself in its tooltip.

**Known limits:** files that are in no
thread manifest have no inventory and cannot be tagged, the favorites gallery offers
no tag target, and there is no managed move or re-link of orphans (none of the three
exists in the source).

## Importing your own files

- **Import files…** (menu), or dropping files and folders on the window, opens the
  import dialog. **Add files…** and **Add folder…** collect the selection; **Include
  subfolders** and **Also other files (PDF, ZIP, audio)** widen it. Other files are kept
  without a preview.
- **Checked before anything is copied.** MeowChan looks through the selection and checks
  every file by SHA-256. The list shows for each file whether it is new, already there,
  selected twice, not supported, too large, not readable or skipped (a link, or already
  inside the download folder). When not all media could be read, the dialog says that
  the duplicate check is incomplete. **Stop check** stops only the looking through.
- **Your originals are never moved or changed.** New files are copied into
  `meowchan-import/` in your download folder; files MeowChan already has are only
  linked. A batch gets a name (up to 200 characters) and, if you like, own tags.
  **Stop after current file** ends the run; files already copied stay imported. When the
  download folder does not have room for the files plus the free-space reserve, the
  import stops before anything is copied. **Show batch** opens the batch on the Media
  page.
- **Imported files are ordinary local media.** They appear on the Media page under
  **Own imports**, in the gallery and among the favorites, and can be tagged and rated
  like everything else. The import catalog is the new profile file `local-imports.json`.
- **Limits are settings.** When a selection hits a limit, the dialog names the setting
  under **Storage and limits** (files and size per batch, largest single file, files in
  total, catalog file size, tags per batch, number of batches).
- Back up `meowchan-import/` together with the profile.

## Danbooru search and watchers

Danbooru is a new, bundled, read-only source (`meowchan.official.danbooru`). It is a
post-search source, not a board or thread source. It is reachable in the app through
**Danbooru search and watchers…** in the Workspace menu, which is shown while the
profile is ready and the Danbooru plugin is enabled. In the intended 1.1.0 behaviour:

- **Enabled by default.** Unlike the experimental chan sources, the Danbooru plugin is
  active after the first start. It sends nothing until you search, load a post or a
  watcher checks; disabling the plugin hides the menu entry.
- **Search and single posts.** A tag search shows previews, the post link, source tags
  and the provider's own rating. MeowChan does not add an automatic rating filter; a
  rating condition you type stays part of your query. A search shows at most 5 pages
  of 20 results; the window says so and suggests a watcher for anything beyond. A post
  link or numeric post id loads exactly one post and creates no watcher.
- **Result cards.** Each result lists rating, score, favorites, date and original file
  as facts, with the same rating and tag-category names as the detail dialog. Every
  source tag is a button that adds it to the search (up to two); nothing is requested
  until you press **Search**.
- **Addresses in the Add field.** Several Danbooru search addresses in one Add input
  open the window with the last one and report the unused ones once; words after a space
  stay part of an address; a dropped board name such as `/g/` counts as a link, not as a
  file.
- **Previews, originals only on request.** Previews are small images fetched through a
  restricted preview path: only the declared preview hosts, GET only, no redirects, no
  credentials, at most 1 MiB and an image signature check. Searching and selecting load
  no original and no sample. Chosen originals go through the ordinary download queue. A
  post already known from another search, one-shot or watcher is not queued twice, and
  its additional finds stay recorded. A sample or preview is never silently used as the
  original. A request for an original is stored before the queue is offered the job, and
  an application stop is not a cancel: a requested original that was running or waiting
  is picked up again at the next start, in the background, so the window does not wait
  for the queue.
- **Watchers.** A saved search can be paused, checked now, resumed or removed. The first
  check sets a baseline instead of downloading the whole history. Checks are bounded
  per run and continue below a post id cursor (`page=b<id>`), so a backlog is caught up
  over several checks without gaps or duplicates and without a page limit.
  A manual check of a paused watcher runs once and leaves it paused; it still honours
  the provider cooldown. After HTTP 429 the watcher waits at least 60 seconds, or the
  provider's longer `Retry-After` up to 24 hours, and is kept. A watcher whose remaining
  posts can no longer be reached offers **restart from now**. Removing a watcher keeps
  all saved media, metadata and finds.
- **Links and a notice.** Every result and every watcher card (for the newest post it
  has seen) offers **Open post in browser** and **Copy link**; both use only the
  canonical post address built from the post number. When an automatic check adds
  originals to the download queue, one notification titled **Danbooru watcher** names
  the watcher and the count; screen readers announce it.
- **Readable errors.** Scheduler, host, port and window error codes each have a sentence
  in English, German, Spanish, French and Russian (Spanish, French and Russian are
  unreviewed machine translations). The window shows a catalog or record fault in the
  watcher list instead of an empty list, an invalid search input is named in text and
  not only by colour, and raw English host or plugin messages do not reach the window.
  Any text that mentions a Danbooru host is redacted from logs and feedback context.
- **Provenance and offline use.** Provider post id and link, rating, score, source
  tags with categories and where each post was found are stored in `booru-catalog.json`,
  separately from your own tags. Requests carry no credentials; a request with
  credentials is rejected by the host. Searching, loading a post and checking a watcher
  need a connection; saved media and stored metadata do not. The catalog is validated
  once and kept in memory, and an original is admitted in a single write. The catalog
  file has a write limit, the setting **Danbooru catalog limit (MiB)** under Settings,
  **Storage and limits** (default 32, 8 to 128). From 75 % the watcher
  list warns and names the setting; at the limit watchers and original downloads cannot
  save new posts, while pausing, resuming, removing and cancelling keep working. Lowering
  it deletes nothing; reads stay bounded by a fixed 128 MiB ceiling.
- **Downloaded Danbooru media in the Media page, gallery and favorites.** Originals
  appear as local media with their origin: a **Danbooru** source filter, a badge, tiles
  that name the post, and a detail dialog with the canonical post link
  (`https://danbooru.donmai.us/posts/<id>`), the original, sample and preview versions,
  where the post was found and the source tags by category, shown apart from your own
  tags. Identical bytes are grouped with archive media. The display survives removing
  the watcher and an offline restart.
- **Source tags from the details.** The detail dialog copies source tags (all, per
  category or the marked ones, written as Danbooru writes them) and puts up to two
  marked tags into the Danbooru window's search field without sending anything; when
  the window is unavailable the query is copied instead.
- **Not offered:** upload, voting, tag editing, accounts, other booru providers, an
  unbounded backfill and own tags on Danbooru media (the tag controls are shown disabled
  with an explanation, because own tags on provider media need a new tag target).

**Pending:** the committed `docs/Help.md` has no Danbooru section yet.

Tests run against an in-memory Danbooru. No run against the live provider is documented,
so its current output and rate behaviour are not verified here. See
[Booru data: upgrading and older versions](v1.1.0-booru-data.md).

## Reader

- **Posts as cards.** The Reader shows every post as a card on the page tone; the
  opening post sits directly on the page. The header is one line (subject, name, date,
  number), and a click on the number copies `>>number` for quoting. Thumbnails lie flat
  under a file line with name and size.
- **Post text.** Post bodies are set in a bundled Noto Sans subset (Latin, Greek,
  Cyrillic; CJK uses the system fonts); the interface stays in Inter. Both fonts are
  credited in About and the README. Lines starting with `>` are green, and `>>number`
  jumps to that post, which flashes once (the quote buttons stay as the keyboard path).
  Quotes of posts that were not captured are struck through, spoilers stay hidden until
  you click them or press Enter or Space, code is monospace and external links are
  underlined. The HTML export shows the same cards, colours and greentext.
- **Quote previews.** Rest the pointer on a quote, or focus a quote button and press
  Space, to preview the quoted post (at most eight lines or 420 characters). Escape
  closes it, Enter on the quote button jumps there. Only captured posts of the same
  thread are previewed.
- **Where you left off.** When you continue reading or load new posts, a line marks the
  first new post ("N new posts since last time"), and **Back to last read** returns to it.
- **Long posts and replies.** Posts over 24 lines fold to 18 with **Show more**
  (remembered per post while the thread is open; find unfolds a post with a hit). The
  reply counter in the header opens the replies as nested cards, five at a time; replies
  always come from saved posts.
- **Toolbar and find.** The Reader toolbar stays on one row and moves its least useful
  actions into **More**. Find in a saved thread, filename search and an exact SHA-256
  search entry (for a thread with exactly one media folder) are available from the
  Reader. **Ctrl/Cmd+F** opens find in the large Reader, Enter runs the focused find
  button, and a failed find offers **Search again**. The reader post menu copies text,
  number and (for 4chan) the link.

## Archive, Downloads and gallery

- **Filters accept what you pick.** In Archive filters, clicking a source or board
  suggestion, pressing Enter on it, or choosing a source state adds it immediately as a
  chip, and **Search** adds leftover text in those fields first. Invalid values stay in
  the field with one message under it. Tags still need an explicit include or exclude.
  The Archive and Media filter fields open as a surface over the results instead of
  pushing the list down.
- **Status messages as an overlay.** Archive status messages appear as a timed overlay
  above the docked footers, so the list and reader boxes run to the page edge. The
  Archive pager sits as a bar inside the results box.
- **Drop links on the window.** Thread and board links dragged onto any page of the main
  window go through the same path as the Add line. Files and folders open the import
  dialog.
- **Downloads.** Removing from the watch list offers **Undo**, retries state the reason
  and the next step in plain language, the tray menu can pause and resume, the search
  also matches the status text, an address that is already watched offers **Show in
  list**, and toasts last by category. Downloads shows the effective parallel limit live.
  **Scan clipboard for URLs** (Settings, off by default) offers supported board and
  thread links from the clipboard in a passive banner; it adds nothing on its own.
- **Gallery.** Keyboard **F** on a saved favorite asks before removing it; **U** removes
  explicitly. A Tags button tags the shown media version. A saved file without a viewer
  shows **Open with default program** and **Show in folder** (runnable types such as
  scripts are never handed to the default program). The export button reads
  **Original…**, the slideshow duration is a dropdown next to the playback mode, and the
  archive media footer has **Manage saved ratings…**.
- **Startup.** Archive, Downloads and Settings are usable while the session is still
  starting; archive reads are separate from writes, which wait for Ready. Downloads
  shows the last known session in its normal table, marked as such, until the first
  authoritative data arrives. Unchanged bundled plugins reuse their validated
  description and bundle verification work.
- **Work journal and downloads.** A single unreadable row in the work journal no longer
  hides the remaining watches; they are restored and the row is reported. A download
  loop that failed is restarted on the next signal, and a failing observer no longer
  holds a transfer slot, so the queue cannot stall silently.
- **Large collections.** The saved media index is written only when it changed, and
  unchanged threads and imported batches are reused without opening their manifests.
  The own tag store and the import catalog are indexed and do not re-parse an unchanged
  backup. The download speed timer stops while the window is hidden or minimized,
  opening a folder on an unresponsive network share no longer freezes the window (2 s
  limit), and chan plugins ask for compressed responses. See
  [Known limitations](#known-limitations) for the Media page on very large collections.
- **Diagnostics.** The app writes a rolling per-user log file outside the profile and
  recovers unexpected UI-thread exceptions with a visible error banner. The log and the
  Diagnostics page name the platform, the window title bar mode and where the
  reduced-motion decision came from. When the device time zone cannot be resolved,
  archive date filters say so and use UTC instead of failing.
- **Focus and window fixes.** Closing the export dialog or returning from the gallery
  now puts focus back on the export button, or on **More** when the button sits in the
  closed overflow menu at narrow widths (focus used to be lost). When saving Settings
  fails validation, the visible error line of the field is scrolled into view, also in a
  small window. The About, Settings and first-run windows keep their normal size after a
  restore from the title bar on Linux/X11, where the window manager used to bring the
  old maximized size back. Several dialogs (archive metadata, gallery details, media
  occurrences, reader groups, saved searches, experimental activation, startup error)
  got a larger minimum height so their footer stays visible.
- **Keyboard shortcuts.** The main pages are numbered in footer order: **Ctrl+1** Downloads,
  **2** Archive, **3** Media, **4** Rules, **5** Sources, **6** Diagnostics, **7** Plugins
  (**Cmd** on macOS); footer, menus and the F1 help share that one order. Tags are **Ctrl+T**
  (thread in the Archive and Reader, media on tiles and in the gallery), the thread favorite
  is **Ctrl+D**, filters are **Ctrl+Shift+F** (board filters moved there from Ctrl+Shift+R),
  and **Ctrl+A** selects all media. The large Reader has find next and previous (**F3** and
  **Ctrl+G**, **Shift+F3** and **Ctrl+Shift+G**). The gallery and Media page gain **S**
  slideshow, **I** details, **R** rating, **Ctrl+E** export original and **Ctrl+O** show in
  folder; in the Archive and Downloads **Ctrl+O** still opens the thread folder. One **Back**
  gesture (**Alt+Left**) answers for previous reading position, back to the gallery and back to
  media, innermost first; one page gesture (**Alt+PageUp/PageDown**) pages results, posts and
  backlinks by focus. On macOS the defaults follow Apple conventions (**Cmd** for Ctrl, no
  gesture that needs Fn, **Cmd+Delete**, **Cmd+Left** for Back, **Cmd+G** find next, **Option+Cmd+R**
  refresh, **Control+Cmd+F** full screen, **Cmd+?** help), shortcuts show as ⌃⌥⇧⌘ glyphs, and
  a native menu bar lists them. **Settings, Keyboard shortcuts** has a switch that turns the
  standard single-character shortcuts off (letters, digits, +, −, ?); Space, Enter, arrows,
  Delete, F keys and Ctrl/Alt/Cmd chords stay. **Your saved shortcuts are never changed.**
  Where a new default meets a shortcut you set for another command, the default steps aside
  for that command and the shortcut editor says so; the startup warning appears only for
  bindings that are really blocked.
- **Smaller fixes.** Stale clipboard offers at startup are suppressed, gallery transport
  shortcuts respect nested editors, HTML export titles wrap in narrow dialogs, and
  playback settings and the shortcut editor follow the language. Export and gallery
  actions are enabled only when their selection is really ready, the Downloads filter
  shows true results while starting, and Media page filters keep their identity across
  refills. Local video probes its audio track once per playback instead of on every
  tick, and the bundled VLC runtime is hashed once per process.

## Appearance and accessibility

- **MeowChan's own title bar.** Every window and dialog uses the app's own title bar.
  Windows and Linux keep Snap, resize and shadow; Windows 11 gets square corners; macOS
  keeps its native traffic lights, full screen and rounded corners with the app caption
  beneath. `MEOWCHAN_WINDOW_CHROME=system` brings back the platform title bar
  everywhere. The tagline moved from the title bar into About.
- **Animations setting.** **Animations** (Follow system, On, Off; default Follow system)
  decides whether short fades, hover, chip and overlay transitions and the motion of
  notifications are played. Follow system uses the operating system's reduced-motion
  setting. Progress bars and spinners always stay. `MEOWCHAN_MOTION=off|on` and
  `MEOWCHAN_REDUCED_MOTION=1|0` take precedence over the setting. See
  [Known limitations](#known-limitations) for menus and popups.
- **Focus and selection by shape.** The keyboard focus ring is drawn in two shells so it
  stays visible on any background. The selected state shows by shape, not only by
  colour: chips, tiles, thread media tiles (a drawn check mark), the settings sidebar
  (a bar) and selected rows and tiles (an accent bar). Hidden spoilers get a neutral name
  for screen readers until revealed, tiles and Danbooru facts have named values, and the
  quote buttons stay reachable with Tab after the post text.
- **Logo by theme.** The light theme shows the orange cat, the dark theme the grey cat,
  switching live in the window icons, tray and dialog icons. The header logo and the About
  window show both cats side by side in either theme. Program and package icons stay
  orange. THIRD-PARTY-NOTICES describe both motifs.
- **Photo credit.** Both cat logos, Simba (orange, the same artwork as the lain logo) and Mila
  (grey), derive from photographs by Alexander Huxel · Webentwicklung Huxel. The credit with links is in
  THIRD-PARTY-NOTICES, the README and the About window's Credits tab (es/fr/ru wording is
  machine-translated).
- **Light theme.** Warm grey surfaces and a muted orange accent (`light-warm-orange`)
  replace pure white panels; dark is unchanged. Interactive outlines use a darker control
  border token (about 4.1:1 on the panel), text fields, combo boxes, check boxes and
  scroll bars are outlined, selected rows and tiles carry an accent bar besides the
  tint, the remaining blue selection and focus colours use the accent, placeholders and
  menu shortcuts use the muted text colour, and the marked favorite uses a dark amber
  (about 4.8:1 on the panel) instead of gold. These ratios are calculated from the theme
  colours; a new measurement of the whole app in the light theme is not recorded.
- **New profiles start in Simple.** A freshly created profile opens in the Simple view,
  so Archive and Media are footer buttons from the first start instead of entries in
  Tools. Existing profiles keep the view they saved; a settings file that stores no view,
  and damaged or unsupported settings, still fall back to Barebones. Switch views in the
  footer at any time.
- **Empty pages name the next step.** An empty Downloads list offers **Add URLs from
  clipboard** (the same import as the paste shortcut and the tray item), an empty Archive
  offers **Go to Downloads** (it replaces the **Reader groups** button there; reader groups
  stay in the toolbar), and an empty Media page offers **Go to Downloads** and **Go to
  Archive**. A search or filter that finds nothing keeps its plain sentence.
- **Dialogs and pages.** Many dialogs use a shared frame with a fixed header, a local
  error strip and a fixed footer around a scrolling body, and Diagnostics, Rules and
  Settings follow the shared page header spacing.

## Settings, updates and languages

- **Update notice.** When MeowChan finds a new version, a quiet notice appears once per
  start with **Release notes**, **Later** and **Skip this version**, and the tray gets
  the same entry; the footer notice stays as the indicator. A skipped version is not
  announced again, and the notice stays away when information popups are off. With
  automatic update checks off it appears only after your own **Check for updates**,
  which also shows a skipped version again. Nothing is downloaded or installed
  automatically; the release notes open in your browser.
- **Storage and limits.** The settings page formerly named after the plugin-process
  expander is now **Storage and limits**, next to the free-space reserve. Amount and size
  limits that used to be fixed are settings there, each with a default, a minimum and a
  maximum: entries per favorite, thread-favorite and rating list (default 50000) and
  their file size (8 MiB), post bookmarks (10000), saved searches (500), reader groups
  (500), the question before **Export all matches…** (500 files or 2 GiB), the video preview
  cache (128 MiB, 256 files), the media index cache (256 MiB, 1000000 entries, 200000
  threads), own tags (1024, up to 20000) and their file (32 MiB), the Danbooru catalog
  (32 MiB) and seven import limits (including 2000 files and 32 tags per batch). Lowering
  a limit deletes nothing and never makes a saved file unreadable; removing, renaming and
  cancelling keep working above a lowered limit. A full list or a refused write names the
  setting in your language, and the status bar warns from 75 % of the favorites, thread
  favorites and ratings limits and of the media index cache, naming the list. Fixed
  technical limits are listed in the help.
- **Downloads settings.** **Media transfer resource limit** (default 32, 1 to 256) is now
  a setting; the effective parallelism is the smaller of **Parallel downloads** and this
  limit. In 1.0.2 the cap of 32 was fixed. Plugin settings say that they apply at the
  next start.
- **Languages.** Spanish, French and Russian are bundled as **Untested** languages next to
  English and German; missing translations fall back to English. German texts are
  consistent: always "du", one wording per action (Reader, Downloads, Beobachtung, Post,
  and Suchbeobachtung for Danbooru watchers), correct singular forms (also Russian 2 to 4),
  and one file-size format that never shows 0 MB for a small file.

## Plugins, sources and SDK 1.1.0

- **Plugin SDK 1.1.0.** Adds the typed booru post-search contract
  (`SourceCapabilities.PostSearch`, `IBooruSourcePlugin`, typed request, page and post
  results) with before-id cursor paging (`BeforePostId` / `NextBeforePostId`, used by
  sources whose post order is `PostOrderKind.DecimalPostId`), and an explicit
  `PluginDeclarationStatus` (property `DeclarationStatus`) for blocked plugin metadata.
  Hosts accept plugins that declare SDK `1.0.0` or `1.1.0`; plugins built for 1.0.0 keep
  working. A plugin that declares post search must declare 1.1.0.
- **SDK API review.** The SDK 1.1.0 surface (173 inventory entries) was reviewed and
  moved from Unshipped to Shipped in `MeowChan.PluginSdk/PublicAPI.Shipped.txt`; see the
  [API review](v1.1.0-api-review.md) (German). The SDK and library stay explicitly not
  stable in 1.x; the review adds no compatibility promise.
  The booru post identity is named `BooruPostId` (renamed from `SourcePostId` after the
  move to Shipped; the API review notes it). The JSON shape is unchanged.
- **One-time bundled-plugin transition.** A bundled plugin whose only change from the
  approved build is the declared SDK version `1.0.0` to `1.1.0` is activated
  automatically at startup once per plugin, keeping enabled state, settings, filter
  grants, restricted-source permissions and source ownership, without a new rights
  review. It requires an exact description match, the same candidate and path, a
  matching delivery record and valid settings. Reverse changes, any additional
  description change, pins, conflicts and any rebuild after a 1.1.0 build was already
  activated (even a failed one) follow the ordinary rules: **Review bundled repairs**,
  explicit authorization, restart. See
  [Updates of bundled plugins](../plugins/using-plugins.md#updates-of-bundled-plugins).
- **Plugin approvals.** Reauthorizations you explicitly tick can be submitted together;
  they are written one after another and stop at the first failure. Approval status is
  announced politely to screen readers, and approval texts exist in Spanish, French and
  Russian.
- **Danbooru in the plugin package.** The Danbooru plugin is part of the bundled plugin
  delivery (24 bundled plugins) and is enabled by default; see
  [Danbooru search and watchers](#danbooru-search-and-watchers).
- **More bundled sources.** SevenChan (7chan), BbwChan, 8chan.moe, Fchan and CapybaraChan
  are bundled as experimental sources, disabled until you activate them. AnonImageboards
  and GuroCx are bundled as documented technical blocks without a route or network
  access. No live availability is claimed for any of them.
- **Source fixes.** 2ch (Dvach) stickers, Uboachan deleted-file markers and 7chan
  threads with unquoted post ids or repeated file links are accepted; 7chan multi-file
  posts name their attachments by file name. An attachment
  without a usable extension, or with metadata the host rejects, is skipped and marked
  invalid instead of failing the whole thread. 2ch no longer passes its provider MD5
  as an integrity expectation (the provider's MD5 and size described a different file
  in the observed runs); a stated MD5 is still validated for format, and the file must
  still match its content length, decode and reopen offline.

## Transfers, imports and exports

- **Import transfer packages.** **Inspect transfer package…** in the Archive header opens
  the import dialog: a package is read, verified and staged before any archive write,
  planned as a new thread or a merge into an existing or 404 thread, and applied only
  on explicit confirmation.
  Existing originals, favorites, ratings and notes are not silently replaced. Several
  threads in one set are applied one after another with a partial-result receipt, not
  atomically. Repeating an import is idempotent. Private metadata is not imported
  silently; a package with private data is refused on an explicit new import instead of
  importing only its public part. **Check again** re-reads a package after you changed it
  on disk, without closing the dialog. (Importing your own loose files is described in
  [Importing your own files](#importing-your-own-files).)
- **Media conflicts.** When a merge brings different bytes for the same place, the
  alternative is recorded and can be reviewed in **Manage conflicts**: keep, discard
  (a discarded alternative is not offered again) or use it as the active version, each
  after confirmation. Discarded alternatives whose files nothing references any more
  can be reclaimed from disk after a confirmation that names the folders.
- **Interrupted imports.** At startup, an import or merge that stopped before its
  commit is offered for discarding in a two-step question. Keeping it, pressing Escape or
  closing leaves the strict recovery state.
- **Exports.** HTML exports follow the language set when the export is started and use
  the Reader's cards, colours and greentext. URL-text export and filename search are
  available from Archive. Copying originals from the Media page is described above.

## Upgrading from 1.0.2

**Close MeowChan and back up your entire profile and media folders first.** Include
`meowchan-import/` in your download folder once you use the file import. Changes below
are made on first start or first use of the new feature. There is no supported
downgrade of data changed by 1.1.0.

**What happens on the first start:**

1. `archive.db` is migrated from schema 5 to 12 in one transaction.
2. The work journal drops rows of superseded media generations, after one checked backup
   (see the table).
3. Bundled plugins take the one-time SDK transition above; the five new experimental
   sources and the two technical blocks appear disabled, Danbooru appears enabled. Local
   `.cs` plugins are recompiled.
4. Your settings are read as before; the new settings start at their defaults, and your
   saved view, shortcuts and plugin choices stay.

The first start creates no `private-tags.json`, `booru-catalog.json` or
`local-imports.json`; each new file appears only when you first use its feature. The
Media page index is built in the background the first time you open the Media page.

| What | What happens | Older versions |
| --- | --- | --- |

**Private tags, version 1 to 2.** The first tag write that touches a loose file converts
`private-tags.json` from version 1 to version 2 (a new section holds the occurrence
registry; archive schema stays 12). It keeps the old file as `private-tags.json.bak` and,
permanently, as `private-tags.v1.bak` (written once, byte-identical, never replaced or
deleted by later writes; the `.bak` is replaced by every later change). Version 1 files
stay byte-identical until then, and later writes keep version 2. Builds that only know
version 1 refuse version 2 and do not overwrite it, and a newer or damaged primary or
backup file is never overwritten or rotated away. To go back to a build that only knows
version 1, close MeowChan and restore `private-tags.v1.bak` as `private-tags.json`; this
loses only the tags on local files and any later tag changes. 1.0.2 itself has no own
tags and ignores both files, so this matters only for builds between 1.0.2 and 1.1.0 that
know version 1.

**Going back.** A downgrade to 1.0.2 is not supported: 1.0.2 refuses the migrated archive
database, so an upgraded profile does not open there. Use a complete pre-upgrade backup
restored to a separate location; do not point 1.0.2 at an upgraded profile. Plugin-state
and tag backups are not full-profile backups (the `.bak` tag backup is replaced by later
writes; only `private-tags.v1.bak` is permanent). Changes made in 1.1.0 after the backup
are not carried back. Going back does not delete saved Danbooru files or imported files,
but whether an older version lists them is not promised.

## Known limitations

- **Windows and macOS are not yet checked on real machines.** Everything
  platform-specific in this release is compiled but has not run there: the own title bar
  with Snap and square corners on Windows, the traffic lights, native menu bar and Cmd
  shortcuts on macOS, the operating system's reduced-motion signal, screen readers (NVDA,
  VoiceOver), 150 % scaling and packaging. **Pending**, see
  [Release process and evidence](#release-process-and-evidence).
- **Further booru providers are planned for 1.2.** The booru family plugins (other
  booru sites beyond Danbooru) are not part of 1.1.0.
- **Danbooru** is anonymous, read-only and limited to the bundled provider. It is
  enabled by default but sends nothing until a search, a loaded post or a watcher check.
  A third-party plugin can declare post search, but only the bundled Danbooru source is
  used by the host.
- **Danbooru watchers can hang until restart.** **Pending fix:** if the Danbooru plugin
  process is stopped or the plugin is disabled while a watcher check runs, that watcher
  can stay in the checking state, **Check now** never finishes and no other watcher runs
  until MeowChan is restarted.
- **"Animations: Off" does not yet reach popups.** **Pending fix:** menus, tooltips,
  flyouts and the quote preview open in their own popup windows, which do not follow the
  setting yet.
- **Media page on very large collections.** In a synthetic collection of 1,000 threads
  and 100,000 files, each filter or sort change blocked the window for about 0.3 to
  0.8 seconds and building the index without a cache took about 14 seconds. A faster
  version is measured but not on this line (**Pending decision**: part of 1.1.0 or a
  later release).
- **Import of special files.** **Pending fix:** a named pipe or device file in an import
  selection (Linux, macOS) can make the import check wait without end, and **Stop check**
  does not end it.
- **Own tags on Danbooru media** are not available; the controls are disabled with an
  explanation. **Own tags on files outside a captured post** work only for files that a
  thread manifest lists or that you imported. Files outside every thread manifest have no
  inventory and cannot be tagged. The favorites gallery offers no tag target. Own tags do
  not travel with transfer packages; the Export dialog states this.
- **Import of private metadata, rootless packages and stale plans stays blocked.** There
  is no user-facing creation of transfer packages in this release line beyond the
  existing HTML and original-file exports.
- **Help.** The committed user guide has no sections yet for the Media page, own tags,
  the Tag manager, the file import, the transfer import dialog and Danbooru (**Pending**).
- **Spanish, French and Russian** are unreviewed machine translations.
- **Experimental sources** are not verified against the live sites.
- **Plugin SDK:** the 1.1.0 additions are Shipped in the public API inventory, but the
  SDK stays not stable in 1.x.

## Release process and evidence

Nothing below is a pass. No exact-source `stable-candidate` run, package inventory,
checksum verification or upgrade run from a real published 1.0.2 profile exists for 1.1.0.
Developer test runs on individual commits are partial evidence and do not combine into
an acceptance of a different commit.

- **Pending:** one exact-source `stable-candidate` run with all required jobs and the
  original asset set, root verification of source identity, inventory and checksums.
- **Pending:** a complete test and smoke run on the final commit. No full suite has run
  on the current base. The last run over all test projects was made 95 commits
  before this base and had 9 failures (one Desktop, one Core scheduler test that fails
  intermittently, seven plugin runtime); the Desktop and plugin runtime failures were
  repaired since, the intermittent Core test is not. A later full run stopped after three test projects.
  Every change since was accepted with targeted tests of the files it touched, so
  interactions (motion and popups, title bar and dialog sizes, shortcuts and the macOS
  menu bar, import and the media index cache) are not covered on the merged state.
- **Pending:** upgrade from a real 1.0.2 profile with two offline restarts. The tooling
  for it is on the development line: a synthetic 1.0.2 profile is generated from the
  pinned 1.0.2 source, opened by the candidate three times (first open plus two offline
  restarts), written to and read back, and checked against the documented upgrade
  results and the phrases of this page. The generator itself has run successfully, and
  one three-process upgrade run passed on an older revision built from a working copy
  with uncommitted changes, so it is not candidate evidence. The one-command runner
  reports `PASS` only together with the Linux package set and `SHA256SUMS` of the
  `stable-candidate` run for the same commit; a source-only run ends as `SOURCE-ONLY`.
  It has not completed on any candidate yet.
- **Pending:** public API evidence on the final commit (`scripts/check-public-api.py
  --release --source-commit <sha>`). The Unshipped to Shipped move is done; the API
  review records the `BooruPostId` rename in its addendum, and the commit-bound evidence
  run is still open.

  longer records the original as cancelled. A stop keeps the stored request, and the
