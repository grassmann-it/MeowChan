# MeowChan 1.1.0: Media page, own tags, Danbooru and plugin SDK 1.1.0

> **Draft / unreleased.** MeowChan 1.1.0 is not published. There is no release date,
> no tag, no downloadable package, no accepted candidate run and no package
> verification. This page is a working draft of the release notes. Statements describe
> the integrated source at the base named in
> [Basis of this draft](#basis-of-this-draft). Source integration is not runtime or release
> acceptance; remaining release gates are marked **Pending** below. The final text will
> be written at publication.

This is a feature release on top of [1.0.2](v1.0.2.md). It adds a Media page over
everything you saved, own tags, an import for your own files, a first Danbooru source
with watchers, a larger set of bundled experimental chan sources and plugin SDK 1.1.0.
The Reader shows posts as cards, every window gets MeowChan's own title bar, the
keyboard shortcuts are reworked, a new **Animations** setting controls motion, a found
update is announced with a quiet notice, most amount and size limits are now
settings, the colour palettes are corrected against measured contrast, Sources & Plugins
share one redesigned page, and seven more interface languages are bundled as untested
previews, with text/plural reviews but no native-speaker acceptance. The footer is regrouped, the three work
views reduce pages and dialogs for real, search has one field with a scope, exports share one dialog, the header graph shows
download and upload and disk read and write, the Reader gets a settings page and a conversation view, and the Media page
sorts by more criteria. Several profile files change or are added on first start. There was no 1.0.3
release; its preparation work is part of 1.1.0. Read
[Upgrading from 1.0.2](#upgrading-from-102) before you replace an existing
installation.

## Media page and own tags

- **A Media page for everything you saved.** A **Media** button next to Archive shows
  every saved media file across all archived threads as a tile grid, sorted by thread
  (default), newest or random. Filter by tags, type, favorites, rating, source, board,
  file name, thread and, for videos, whether they have sound. Saved files that are
  missing can be shown. Tiles show your favorite mark, rating and own tags and the
  local video poster, and tags can be edited on the tile. Tiles show their state in
  fixed corners (type, provider, not saved, **No media tags yet**, a favorite star on
  hover or focus); a grouped tile shows the favorite state of its occurrences. The page
  opens the shown files as a gallery and jumps to the post in its thread. From the
  gallery, **To media** returns to the page; from the thread, **Back to media**
  (Alt+Left) returns to the same view with its filters, order, selection and scroll
  position. The page reads a derived index that loads in the background with a status
  instead of freezing the window; the index cache is disposable and rebuilt when
  damaged or when its version changes.
- **Active filters stay visible.** Every active Media page filter shows as a removable
  chip under the toolbar, also while the filter area is closed, with **Reset all** and a
  count on the button ("Filters (3)"). **Without media tags** and a clickable
  "N without media tags" count give you a place to start tagging.
- **Duplicates are grouped, not merged.** Files with the same SHA-256 appear once with
  an "in N threads" hint that lists every occurrence (source, board, thread, file name,
  own tags, **Show in thread**). Tags stay with each occurrence and are never copied
  between them.
- **More ways to sort.** Next to **By thread**, **Newest first** and **Random**, the page sorts
  by **Captured**, **File name**, **Size**, **References** (saved occurrences of the same bytes),
  **Tag count** (own media tags plus the thread's tags) and **Rating**, and a direction button
  next to the choice reverses it (Random has none). Files without a value (no name, never saved,
  unrated) stay last in both directions, and a group of identical files counts its highest tag
  count or rating. The criterion and direction are saved and restored; **Random** returns to
  the last non-random criterion and direction on the next start.
- **Select, tag and export from the page.** Ctrl/Cmd+click, Shift+click and Ctrl/Cmd+A
  select tiles. A selection can be tagged together in one all-or-nothing write, opened
  as a gallery or exported as originals. **Export all matches…** exports one original per
  shown tile through the existing export dialog and asks first above 500 files or
  2 GiB (both are settings). Tiles that are unsaved or have no original are counted as
  unavailable, not skipped silently.
- **Several files in a thread's media tab.** A thread's media tab selects like the
  Media page: Ctrl/Cmd+click, Shift+click, Shift+arrows, Ctrl/Cmd+A and Esc. With two
  or more files selected, **Tag together…**, **Selection as gallery**, **Export
  originals…** and **Clear selection** act on all of them, also from the right-click
  menu; every other command still acts on the file you clicked.
- **Own tags.** Tags are private to your profile and stored in `private-tags.json`.
  Tag a thread from the Reader (tag bar with `/name/` suggestions taken from the title
  and first post) or with **Tags…** in the Archive thread menu, and tag the exact shown
  media version from the gallery. Your own tags are suggested while you type. Threads
  show their tags in the thread list and table. The Archive filter can include or
  exclude tags (all or at least one included), saved searches describe tag filters by
  name, and the **Tag manager** lists thread and media counts, renames tags and deletes
  them after a question that names both counts. Thread and media tags do not inherit
  from each other.
- **Tag dialogs built around search.** One field filters a single list of toggle rows
  with use counts: the tags on the file first, then the most used, then A to Z (or sort
  by most used), with one-step undo from the footer. Tagging several files together
  shows for each tag whether all, some or none of them carry it ("3 of 5"). The Tag
  manager offers the same sort choice.
- **Quick tagging panel in the gallery.** **Tags** in the gallery (also
  **Ctrl/Cmd+Shift+T**) opens a quick tag panel in the slot of the post panel instead of the tag
  dialog. The two panels exclude each other (**P** returns to the post panel) and the placement
  rules of the post panel apply: docked from 900 dip, floating over the picture below, with a
  **Post | Tags** switch and a resizable width of 280–480 dip. The panel
  follows the gallery from file to file: each shown medium gets a fresh target frozen to exactly
  that file ("Medium 4 of 27", announced politely), the undo steps and the text in the field stay,
  and a medium that cannot be tagged is named with its reason instead of silently keeping the
  previous file's target. It shows the tags on the file, numbered suggestions ranked from the
  context (used often, used recently, from this thread, on nearby media, same file elsewhere, from
  the file name or thread title, and Danbooru source tags offered as new own tags), **Undo** (which
  names the other medium when it undoes a change made there) and a **Thread tags** section; thread
  tags stay a separate list because they mark the thread and not its files. Default keys, all
  rebindable and yielding to a saved binding of another command: **Page Down** and **Page Up**
  for the next and previous medium (**Cmd+Down** and **Cmd+Up** on macOS), **Ctrl/Cmd+Enter** to
  add the typed tag and go on, **Ctrl/Cmd+T** for the thread section, **Ctrl/Cmd+Z** to undo
  (text entry keeps text undo) and **Alt+1** to **Alt+9** for suggestions (**Cmd+1–9** on macOS).
  **Advanced…** opens the full tag dialog (occurrences, sorting, long lists) and the panel reloads afterwards. The panel texts exist in all 12
  languages, with language/plural reviews but no native-speaker acceptance of the preview packs.
- **Quick tagging outside the gallery and on marked media.** **Tag…** on the Media page,
  Reader attachments and Archive media tiles opens an anchored popover with the same suggestions,
  stamp and undo as the gallery panel; **Advanced…** still reaches the full dialog. In the gallery,
  **Shift+Page Down** marks the shown medium and advances; **Shift+Page Up** goes back and removes
  the reached medium's mark. Changes then act on the explicitly marked media, not an unmarked
  shown file. A mixed tag can be given to all or removed from all; **Clear marks** ends the
  selection. The marked-media setting bounds it. The favorite/rating row uses the shown or marked
  media too; **Shift+1–5** sets a rating and **Shift+0** clears it, without replacing text entry.
  These are integrated TP3/TP4 controls, not pending implementations; native interaction acceptance
  on the combined source remains open.
- **A shared tag stamp and a tagging queue.** Right-click an own-tag chip to edit the profile's
  stamp, shared by the gallery panel, popovers and **Tagging** page and saved in settings.
  **Stamp** / **Ctrl/Cmd+Shift+Enter** applies missing stamp tags explicitly, one undo step per tag.
  **Add to tagging queue** (**Q** where available) stores work for later in `tag-queue.json`
  without assigning tags, favorites or ratings. Open **Tagging** from the app's **⋯** menu,
  not a numbered footer button, to edit the stamp, reorder entries and start or continue a walk.
  Removing entries or clearing the queue leaves media and their metadata alone; missing files are
  reported, not marked finished. The tools entry **Walk through tagging queue** also resumes it.
- **Tagging walks and cards.** In a walk, **Enter** finishes and advances, **Space** skips and
  **Backspace** takes back the newest step; undoing a queue decision returns to that medium.
  The tag field keeps its typing keys: Enter adds text, empty-field Enter finishes, and
  Ctrl/Cmd+Enter adds and finishes. The stamp chord applies the stamp and advances only on success.
  **K** toggles card mode; outside text entry and the tag panel, **1–5** choose the visible decision
  cards (initially Back, Skip, Favorite & next, Stamp & next, Done & next). **Shift+Space** controls
  playback outside the tag panel. **Settings → Reading & media → Tagging** controls stamp size,
  walk size, decision undo depth and cards. Queue size/history/file limits are under **Storage and
  limits**; lowering limits does not delete tags or media.
- **One chip look.** Own tags are filled, thread tags carry a house mark and Danbooru
  source tags have a dashed outline and a category mark, so they differ by shape and not
  only by colour.
- **Tags protect what they mark.** A thread with an own tag, or with a tagged media
  version, is protected from archive cleanup. Permanently deleting a thread removes
  its tag assignments and reports a failed cleanup instead of hiding it.
- **Tags follow a re-check.** When a source changes what it reports about an attachment,
  tags on the old attachment key are handed over to the new key for the same
  attachment and the same bytes. Different bytes do not inherit tags.

- **Loose and legacy files can be tagged.** Saved files that are not bound to a
  captured post (not assigned, or only matched to a post through the old metadata
  comparison) are taggable from the gallery, the Archive menu, the Media page and
  batch tagging, through one shared target resolver. Each such file has its own
  occurrence identity (thread, media folder and requested file name) with a revision
  per published asset; the bytes, hash and path locate the file but are not its
  identity. The same bytes in two places are two occurrences. New bytes in the same
  place are a new revision that does not inherit tags. Tags of a bound view are never
  copied to a loose view or back. Every add checks the file again and hashes it
  completely, which takes noticeable time for large videos.
- **Missing or replaced files keep their tags as orphans.** A file that is missing,
  moved, replaced or has since become bound keeps its assignments, still counted and
  removable. **Check tagged loose files** in the Tag manager lists them and removes
  exactly the checked assignments; unreadable evidence is counted as "not checkable",
  never as an orphan. Permanently deleting a thread removes its thread, bound and loose
  assignments and its loose registrations but keeps the tag definitions; a failed cleanup
  is reported and can be repeated with **Retry tag cleanup** in the delete dialog.
- **Own tags are not exported.** Transfer packages and original exports carry no own
  tags; the Export originals dialog says so before the export.

- **One media context menu everywhere.** The Media page, Archive table, tiles and inline
  attachments, the gallery and the video overlay share one right-click menu with the same
  order, labels and reasons; it acts on the right-clicked item (also with Shift+F10 and the
  Menu key), and the gallery menu now offers own tags and **Copy file path**. A disabled
  entry explains itself in its tooltip.

**Known limits:** an arbitrary file outside every thread manifest, own import or registered
folder source has no inventory and cannot be tagged. The favorites gallery offers no tag
target, and there is no managed move or re-link of orphans.

## Importing your own files

- **Import files…** (menu), or dropping files and folders on the window, opens the
  import dialog. **Add files…** and **Add folder…** collect the selection; **Include
  subfolders** and **Also other files (PDF, ZIP, audio)** widen it. Other files are kept
  without a preview.
- **Checked before anything is copied.** MeowChan looks through the selection and checks
  every file by SHA-256. The list shows for each file whether it is new, already there,
  selected twice, not supported, too large, not readable or skipped (a link, or already
  inside the download folder). When not all media could be read, the dialog says that
  the duplicate check is incomplete. **Stop check** stops only the looking through.
- **Your originals are never moved or changed.** New files are copied into
  `meowchan-import/` in your download folder; files MeowChan already has are only
  linked. A batch gets a name (up to 200 characters) and, if you like, own tags.
  **Stop after current file** ends the run; files already copied stay imported. When the
  download folder does not have room for the files plus the free-space reserve, the
  import stops before anything is copied. **Show batch** opens the batch on the Media
  page.
- **Imported files are ordinary local media.** They appear on the Media page under
  **Own imports**, in the gallery and among the favorites, and can be tagged and rated
  like everything else. The import catalog is the new profile file `local-imports.json`.
- **Limits are settings.** When a selection hits a limit, the dialog names the setting
  under **Storage and limits** (files and size per batch, largest single file, files in
  total, catalog file size, tags per batch, number of batches).
- Back up `meowchan-import/` together with the profile.

## Danbooru search and watchers

Danbooru is a new, bundled, read-only source (`meowchan.official.danbooru`). It is a
post-search source, not a board or thread source. Open the **Booru** main page after
Media in the Work group, from the footer or **More**, or through **Danbooru search and
watchers…** in the app menu. These routes reach the same page, not a separate window
or Status segment; it has no page-specific Back/Close button. The source must be
composed and available, its plugin enabled and **Show Booru** on.

- **A display switch, not a pause.** **Show Booru** in the footer and app menu is saved
  per profile and on by default; without composed Booru services neither switch nor page
  destination is offered. Turning it off hides the footer, More and app-menu destinations
  and **Media → More → Open Booru**; the page shortcut cannot open the hidden page.
  If selected, the shell returns to Downloads. Showing it again keeps the unsent draft
  while the same source composition remains. This neither activates a plugin nor pauses,
  resumes or authorizes watchers/downloads. Opening or prefilling sends no search; saved
  active watchers continue under their own schedule, pause and cooldown rules.

- **Enabled by default.** Unlike the experimental chan sources, the Danbooru plugin is
  active after the first start. It sends nothing until you search, load a post or a
  watcher checks; plugin availability and the display switch gate the page routes.
- **Search and single posts.** A tag search shows previews, the post link, source tags
  and the provider's own rating. MeowChan does not add an automatic rating filter; a
  rating condition you type stays part of your query. A search shows at most 5 pages
  of 20 results; the page says so and suggests a watcher for anything beyond. A post
  link or numeric post id loads exactly one post and creates no watcher.
- **Result cards.** Each result lists rating, score, favorites, date and original file
  as facts, with the same rating and tag-category names as the detail dialog. Every
  source tag is a button that adds it to the search (up to two); nothing is requested
  until you press **Search**.
- **Addresses in the Add field.** Several Danbooru search addresses in one Add input
  prefill the Booru page with the last one and report the unused ones once; words after a space
  stay part of an address; a dropped board name such as `/g/` counts as a link, not as a
  file.
- **Previews, originals only on request.** Previews are small images fetched through a
  restricted preview path: only the declared preview hosts, GET only, no redirects, no
  credentials, at most 1 MiB and an image signature check. Searching and selecting load
  no original and no sample. Chosen originals go through the ordinary download queue. A
  post already known from another search, one-shot or watcher is not queued twice, and
  its additional finds stay recorded. A sample or preview is never silently used as the
  original. A request for an original is stored before the queue is offered the job, and
  an application stop is not a cancel: a requested original that was running or waiting
  is picked up again at the next start, in the background, so the page does not wait
  for the queue.
- **Watchers.** A saved search can be paused, checked now, resumed or removed. The first
  check sets a baseline instead of downloading the whole history. Checks are bounded
  per run and continue below a post id cursor (`page=b<id>`), so a backlog is caught up
  over several checks without gaps or duplicates and without a page limit.
  A manual check of a paused watcher runs once and leaves it paused; it still honours
  the provider cooldown. After HTTP 429 the watcher keeps a wait of at least 60 seconds;
  the provider's longer `Retry-After` is bounded by the configured cap below. A watcher whose remaining
  posts can no longer be reached offers **restart from now**. Removing a watcher keeps
  all saved media, metadata and finds.
- **Cooldown limit and reset.** **Danbooru Retry-After cooldown maximum (hours)** in Settings caps a
  provider-requested wait (default 24 hours, range 1 to 168 hours); the 60-second floor stays.
  **Reset Danbooru cooldown** in the watcher area clears the local provider cooldown through
  a controlled barrier across transport, scheduler and saved watcher state. The reset itself
  sends no HTTP request and removes neither the global pause nor an individual watcher pause.
  It refuses a running watcher check, preserves a late HTTP 429 and keeps the transport fence
  if saving fails. **Check now** is not a cooldown bypass.
- **Pause, maintenance and plugin switches.** The global session pause stops automatic
  checks only: a check already reading a page finishes that page and stops before the next, and
  **Check now** still runs one check without unpausing the session or bypassing a provider
  cooldown (individual pauses and cooldowns are kept). While MeowChan takes the profile exclusively
  for a maintenance step, watcher checks and commands answer that the profile is busy, a running
  check ends with its recorded result (a late 429 cooldown is kept), and watchers resume afterwards
  unless recovery is required. Disabling the Danbooru plugin revokes the watcher's ports at once and
  enabling it again builds a fresh watcher over the same original queue; on quit, watchers stop
  first and the transports stay until the queue has drained.
- **Links and a notice.** Every result and every watcher card (for the newest post it
  has seen) offers **Open post in browser** and **Copy link**; both use only the
  canonical post address built from the post number. When an automatic check adds
  originals to the download queue, one notification titled **Danbooru watcher** names
  the watcher and the count; screen readers announce it.
- **Readable errors.** Scheduler, host, port and page error codes each have a sentence
  in all 12 interface languages (the ten preview packs have language reviews, not
  native-speaker acceptance), including the paused-session and busy-profile cases. The page shows a catalog or record fault in the
  watcher list instead of an empty list, an invalid search input is named in text and
  not only by colour, and raw English host or plugin messages do not reach the page.
  Any text that mentions a Danbooru host is redacted from logs and feedback context.
- **Provenance and offline use.** Provider post id and link, rating, score, source
  tags with categories and where each post was found are stored in `booru-catalog.json`,
  separately from your own tags. Requests carry no credentials; a request with
  credentials is rejected by the host. Searching, loading a post and checking a watcher
  need a connection; saved media and stored metadata do not. The catalog is validated
  once and kept in memory, and an original is admitted in a single write. The catalog
  file has a write limit, the setting **Danbooru catalog limit (MiB)** under Settings,
  **Storage and limits** (default 32, 8 to 128). From 75 % the watcher
  list warns and names the setting; at the limit watchers and original downloads cannot
  save new posts, while pausing, resuming, removing and cancelling keep working. Lowering
  it deletes nothing; reads stay bounded by a fixed 128 MiB ceiling.
- **Downloaded Danbooru media in the Media page, gallery and favorites.** Originals
  appear as local media with their origin: a **Danbooru** source filter, a badge, tiles
  that name the post, and a detail dialog with the canonical post link
  (`https://danbooru.donmai.us/posts/<id>`), the original, sample and preview versions,
  where the post was found and the source tags by category, shown apart from your own
  tags. Identical bytes are grouped with archive media. The display survives removing
  the watcher and an offline restart.
- **Source tags from the details.** The detail dialog copies source tags (all, per
  category or the marked ones, written as Danbooru writes them). While the originating
  Booru page composition remains available, **Use as search** puts up to two marked tags
  into its search field without sending anything. Hiding the page or losing that source
  withdraws the action; it does not silently become a copy. Explicit copy actions remain.
- **Not offered:** upload, voting, tag editing, accounts, other booru providers, an
  unbounded backfill and own tags on Danbooru media (the tag controls are shown disabled
  with an explanation, because own tags on provider media need a new tag target).

- **Local links between Booru and Media.** **Show in Media** targets the exact saved post
  with local source/post filters and focus, clearing incompatible transient filters; it
  does not search the provider or download an original. **Media → More → Open Booru**
  returns to the available page without searching. A missing local target is reported,
  not replaced by a different post.

See the [Booru page and display switch in Help](../Help.md#booru-page-and-display-switch).

Tests run against an in-memory Danbooru. No run against the live provider is documented,
so its current output and rate behaviour are not verified here. See
[Booru data: upgrading and older versions](v1.1.0-booru-data.md).

## Reader

- **Thread and view tools.** **Thread ▾** groups thread actions; **Show new posts
  automatically** in **View ▾** replaces the old **Follow live** wording.
  **View → Reader settings…** opens quick settings that save and apply immediately;
  **All reader settings** opens the full Settings draft with its separate Save/Discard.
- **Local reading history.** Opt-in **Remember the last reading position locally** keeps
  one position per thread. Right-click **Continue reading** for recent threads (default
  10, configurable 5–25). Its book icon is left of Pause when a position is available
  and neither Reader nor gallery is open; the labelled app-menu command remains available.
  Continue is an explicit local action, not automatic navigation or a provider request.
  **Forget reading position** clears position/history immediately; saving the feature off
  also clears them.
- **Optional larger media, sidebar and inline video.** View and Reading & media settings
  offer enlargement for textless/focused posts and pointer hover. The large Reader's
  media sidebar is off by default, resizable, left or right, and hides below its configured
  reader width. **Play videos in the reader** and **Autoplay videos muted** are separate
  opt-ins, both off by default, using verified saved files only. One inline video plays at
  a time; it pauses when out of view or covered, with a bounded player count and file-size
  limit. Unsupported or oversized media keep the gallery route. Native playback and
  platform behavior still need acceptance.
- **Posts as cards.** The Reader shows every post as a card on the page tone; the
  opening post sits directly on the page. The header is one line (subject, name, date,
  number), and a click on the number copies `>>number` for quoting. Thumbnails lie flat
  under a file line with name and size.
- **Post text.** Post bodies are set in a bundled Noto Sans subset (Latin, Greek,
  Cyrillic; CJK uses the system fonts); the interface stays in Inter. Both fonts are
  credited in About and the README. Lines starting with `>` are green, and `>>number`
  jumps to that post, which flashes once (the quote buttons stay as the keyboard path).
  Quotes of posts that were not captured are struck through, spoilers stay hidden until
  you click them or press Enter or Space, code is monospace and external links are
  underlined. The HTML export shows the same cards, colours and greentext.
- **Quote previews.** Rest the pointer on a quote, or focus a quote button and press
  Space, to preview the quoted post (at most eight lines or 420 characters). Escape
  closes it, Enter on the quote button jumps there. Only captured posts of the same
  thread are previewed.
- **Where you left off.** When you continue reading or load new posts, a line marks the
  first new post ("N new posts since your last visit", a divider across the card width),
  and **Back to last read** returns to it. Its tooltip explains the difference from the
  toolbar's back button, which returns to where you followed a quote or link from.
- **Long posts and replies.** Posts over 24 lines fold to 18 with **Show more**
  (remembered per post while the thread is open; find unfolds a post with a hit). The
  reply counter in the header opens the replies as nested cards, five at a time; replies
  always come from saved posts.
- **Links in posts.** An external link in a post is clickable but opens only after a
  confirmation that shows the full address, with the host in its ASCII form and
  highlighted. The confirmation starts on **Cancel**, so a held Enter cannot open the link;
  screen readers hear the full address, Tab stays inside the dialog and reader shortcuts do
  nothing while it is open. Only visible text that is a complete http or https address of at
  most 2048 characters counts as a link; an address with a user name, hidden Unicode format
  characters (direction overrides, zero-width characters) or a host that cannot be written in
  ASCII stays plain text. A link that could not be started (no default browser) is reported in
  your language. Hover, focus, a text selection and a hidden spoiler never open a link, and
  "Don't ask again this session" is not saved. The HTML export keeps plain links.
- **View menu.** **View** in the large Reader offers **Hide media** and **Only posts with
  media**. Both apply to every thread in the Reader for the session and are not saved. A
  deliberate jump to a hidden post (through a quote, find, a bookmark or the reading position)
  shows it temporarily, and **Hide again** hides it once more. The Reader cuts its pages from one
  projection of the thread, so Up and Down, paging, the reading mark and the retained position
  follow the order that is shown; with nothing switched on the projection is the identity.
- **Conversation view.** **View, Show as conversation** nests a reply beneath the most recent
  earlier post it quotes, but only when its other earlier quotes (the opening post excepted) lie
  on that post's ancestor line; otherwise the reply stays at the top level. The opening post stays
  first, the separate reply counter is omitted, and replies deeper than the maximum indentation
  depth stay visible at the last indentation level. It reorders saved posts only and sends no
  request; the switch lasts for the session and is not saved.
- **Reader display settings.** **Settings, Reading & media** has two groups, **Display** and
  **Long posts and previews**. Changes stay in the Settings draft until **Save** succeeds; then
  they apply to the open Reader at once and keep the reading position, and **Discard draft**
  restores the saved values. An invalid number blocks the save and names the field.

  | Setting | Default | Allowed |
  | --- | --- | --- |
  | Preview image width (px); the large Reader uses 1.5 times | 240 | 120 to 480 |
  | Fold long posts above (lines) | 24 | 8 to 400 |
  | Lines in quote previews | 8 | 3 to 40 |
  | Quote preview delay (ms) | 300 | 0 to 2000 |
  | Reply cards per step | 5 | 1 to 50 |
  | Lines per reply card | 4 | 1 to 20 |
  | Posts per reader page | 50 | 20 to 200 |
  | Maximum conversation indentation depth | 6 | 1 to 16 |

  **Posts per reader page** changes the Reader's paging, not the Archive list. **Spoilers**
  offers **Keep hidden** (default), **Show on hover** and **Always show**. **Date and time
  format** offers **System format** (default), **Weekday and seconds**, **Since opening post**
  and **Relative to now**; the exact local date stays in the tooltip, **Since opening post** falls
  back to the system format when the opening post has no time, and relative text is calculated
  when the page is drawn and not refreshed by a timer.
- **Quote markers.** A reference to the opening post gets a "(OP)" marker behind it and a
  reference to another thread "(other thread)" (screen readers hear "opening post" and "in
  another thread"); the quoted post is outlined while the pointer rests on the reference.
- **Post filters.** **View, Post filters…** opens a dialog for rules and individually hidden
  posts. A rule matches the post text, the subject, a file name or an MD5 (hex or base64, compared
  by its 16 bytes) and hides the post, shortens it to a placeholder or highlights it; **also hide
  replies** follows the quote graph. **Hide post** and **Show post again** are in the post menu
  and have shortcuts. Reply cards and quote previews of a filtered post say so. Nothing is
  deleted, and the HTML export always contains every saved post. Rules and hidden posts live in
  the new profile file `post-filters.json` (one backup, explicit recovery of a damaged file). The
  lists hold 200 rules (20 to 2000) and 10000 hidden posts (1000 to 100000) by default; both
  limits are settings under **Storage and limits**, and lowering one keeps existing entries and
  only stops growth. A rule's **Edit** button loads it into the form and **Save changes** replaces
  it in place (Enter in the search text saves; rules from a newer version stay read-only). Post
  filters are not part of the user-facing profile transfer.
- **Navigation cross.** The lower-right cross is a pure overlay: it reserves no side lane, the
  content uses the full width, and only its four buttons take clicks. It rests at 60 percent
  opacity and fades out after 2 seconds without pointer movement; pointer movement over the
  Reader, the pointer over or within 64 dip of it, keyboard focus and a navigation shortcut bring
  it back, and under reduced motion it switches instantly. The extra margin after the last post
  is gone: it made the list's extent depend on whether the last post was realized, so a jump to
  the last post of a page could end thousands of dip off screen.
- **Enter and jumps.** **Enter** without a selection stays the media key on a post that has
  media (the focused body opens its only link only when the post has nothing to open in the
  gallery). A reader jump ends when you take over and still reports the position it reached.
- **Card layout.** A card with media is one block: the favorite star shares the file
  line and the thumbnail starts right below it in a 16:9 slot; the width of the card is
  set by **Post width** (next bullet). The attachment is as wide as the drawn
  picture (the file line keeps a 140 dip minimum, then wraps and trims), the click frame,
  play button and star sit on the picture, and the 16:9 slot is reserved only until the
  thumbnail has loaded; Archive and Media page tiles keep their cell but letterbox the
  picture and anchor their marks to its corners. Posts of an archived thread are looked up by id from a cached index,
  and focusing the last post of a freshly loaded page ends at the right place.
- **Post width.** The setting **Post width** (Reading & media) has three modes. **Fit to
  content** (default) makes each post card as wide as its header, text and media need, up
  to a reading width of 1120 dip, left-aligned like a post on an imageboard, and the
  opening post follows the same rule. **Centered column** gives every card the full
  reading width in the middle. **Full width** stretches every card across the whole
  Reader. The open Reader follows a change at once; the "new posts" line keeps its
  full-width divider.
- **Toolbar and find.** The Reader toolbar stays on one row and moves its least useful
  actions into **More**. Find in a saved thread, filename search and an exact SHA-256
  search entry (for a thread with exactly one media folder) are available from the
  Reader. **Ctrl/Cmd+F** opens find in the large Reader, Enter runs the focused find
  button, and a failed find offers **Search again**. The reader post menu copies text,
  number and (for 4chan) the link.

## Archive, Downloads and gallery

- **Filters accept what you pick.** In Archive filters, clicking a source or board
  suggestion, pressing Enter on it, or choosing a source state adds it immediately as a
  chip, and **Search** adds leftover text in those fields first. Invalid values stay in
  the field with one message under it. Tags still need an explicit include or exclude.
  Media uses an inline filter section with an always-visible active-chip row. Tag, type,
  source and board chip bodies toggle include/exclude; × removes a chip. **+ Filter**
  searches groups, and included tags offer **all | any**. Query terms such as
  `type:video -tag:wip rating:>=3 sound:none fav` become chips on Enter; unrecognized
  terms stay visible with an explanation. **Copy filters as text** copies applied filters.
  **Shift+F** hides Media tools for grid space while retaining result/filter counts;
  Esc restores them before clearing selection. Focus mode is not saved.
- **Status messages as an overlay.** Archive status messages appear as a timed overlay
  above the docked footers, so the list and reader boxes run to the page edge. The
  Archive pager sits as a bar inside the results box.
- **Drop links on the window.** Thread and board links dragged onto any page of the main
  window go through the same path as the Add line. Files and folders open the import
  dialog.
- **Downloads.** Removing from the watch list offers **Undo**, retries state the reason
  and the next step in plain language, the tray menu can pause and resume, the search
  also matches the status text, an address that is already watched offers **Show in
  list**, and toasts last by category. Downloads shows the effective parallel limit live.
  **Scan clipboard for URLs** (Settings, off by default) offers supported board and
  thread links from the clipboard in a passive banner; it adds nothing on its own.
- **Gallery.** Keyboard **F** on a saved favorite asks before removing it; **U** removes
  explicitly. A Tags button opens the quick tag panel for the shown media version (see above;
  **Advanced…** reaches the full dialog). A saved file without a viewer
  shows **Open with default program** and **Show in folder** (runnable types such as
  scripts are never handed to the default program). The export button reads
  **Original…**, the slideshow duration is a dropdown next to the playback mode, and the
  archive media footer has **Manage saved ratings…**.
- **Gallery image cache and preloading.** The gallery keeps images it has decoded at display
  size in a memory-bounded cache and decodes the next and previous images in the background
  after one is shown, so stepping through shows them at once. The work waits while the shown image
  loads and stops when you move on, videos and GIFs are skipped, and a kept image is shown only
  while its file is unchanged since it was verified. Three settings under **Storage and limits**:
  **Gallery images kept in memory (MiB)** (default 256, 0 turns the cache off, up to 4096) and
  the number of next and previous images decoded ahead (3 and 2 by default, 0 to 20). The
  preload works from a copy of only the shown image and its configured neighbours, taken on the
  interface thread, and never reads the live gallery list from the background; a long gallery is
  not copied at each step. Archive
  tiles and reader attachments now lease their previews from the Media page's preview cache
  instead of decoding again when they scroll back into view.
- **Gallery cache integrity.** A kept image is shown only while its file is still the same
  regular file: the check uses the file's identity and not only its length and time, so a
  same-length rewrite with the time restored and a rename over the file are caught, a missing or
  linked file is never a hit, and a second copy of the same bytes in another folder is verified
  once before it shares the decoded image.
- **Gallery fit.** **Enlarge small images when fitting** (Settings, Reading & media, Gallery &
  playback) is **No limit** by default, so Fit may fill the viewport; **Up to a limit** stops Fit
  at a percentage (default 200, 100 to 1600). Manual zoom is never capped, and **No limit** keeps a
  valid percentage for later.
- **Local video posters.** The Archive thread list, Reader attachments, Reader media and the
  Media page show the verified local poster of a video. A poster is shown only after the local
  original has been checked, no source thumbnail address is fetched, and a cached poster never
  stands in for a missing original. Making a poster is bounded: when the decoder or the
  12-second limit stops it, the video has no poster this time, the failure is not remembered
  and a later view tries again; a request that you cancel still counts as cancelled, and the
  caller never waits longer than 14 seconds. The gallery itself still plays the video.
- **Gallery toolbar and side panel.** **Back to {target}** is alone at the top right,
  with the favorite star to its left. Previous/position/Next, Fit, 1:1, post panel and
  Tools stay available. Rating, tags and slideshow controls move from More in Barebones
  onto the bar in Simple; Advanced also brings playback mode and shortcut help onto it.
  Zoom steps, original export, saved ratings, frame saving, video rules, overlays and
  fullscreen stay under More. Narrow layouts use icons and an over-picture side panel.
  The file plate shows binary size and exact bytes. The optional virtualized filmstrip
  (**L**) lets you jump to neighbouring media; very short windows omit it.
- **Video transport, zoom and rotation.** The transport offers an **A–B loop** (A sets
  start, end, then clears), next frame (**.**), hover volume, speed choices and a player
  menu. Video supports zoom and pan like images; **Shift+R** rotates the view 90° without
  changing the original. Rotation resets for the next medium. A failed reopen is not
  presented as an applied rotation.
- **Seek-bar previews.** Hovering the local video's seek bar can show a positional thumbnail
  and time without seeking or loading a remote preview. The lazy cache is connected to
  the gallery/player and the profile budget **Video scrub preview cache size (MiB)**
  (128 by default, 8–4096). A missing or cancelled preview does not replace playback;
  leaving the bar or changing media withdraws the old request. This is source integration,
  not a native playback/hover-preview acceptance claim.
- **Playback and overlays.** **Manual**, **Repeat current video** and **Slideshow** are
  distinct modes. A saved slideshow mode never starts automatic advancement by itself;
  slideshow must be started explicitly. Seeking and unsafe interactions hold advancement,
  and opening a hover post stops it until explicitly restarted. **Hide controls after**
  shares one delay between gallery overlays and the Reader navigation cross. Esc closes
  the topmost panel/help/dialog first. Media focus and F11 fullscreen remain separate.
- **Startup.** Archive, Downloads and Settings are usable while the session is still
  starting; archive reads are separate from writes, which wait for Ready. Downloads
  shows the last known session in its normal table, marked as such, until the first
  authoritative data arrives. Unchanged bundled plugins reuse their validated
  description and bundle verification work.
- **Work journal and downloads.** A single unreadable row in the work journal no longer
  hides the remaining watches; they are restored and the row is reported. A download
  loop that failed is restarted on the next signal, and a failing observer no longer
  holds a transfer slot, so the queue cannot stall silently.
- **Large collections.** The saved media index is written only when it changed, and
  unchanged threads and imported batches are reused without opening their manifests.
  The own tag store and the import catalog are indexed and do not re-parse an unchanged
  backup. The rate measuring behind the header graph and the statistics runs only while the window is shown (or, with
  tray statistics on, while it is hidden and downloads run),
  opening a folder on an unresponsive network share no longer freezes the window (2 s
  limit), and chan plugins ask for compressed responses. See
  [Known limitations](#known-limitations) for the Media page on very large collections.
- **Startup and return speed.** The plugin pipeline starts its read-only part (reading
  the profile, scanning the inventory, importing and describing candidates) while the
  window and the catalog come up, instead of idling for a moment first; activation and
  rights are unchanged and the plugin startup phases can be measured, also on a warm start.
  A start that changes nothing no longer rewrites the plugin profile file. On the Media
  page, stored sound results show at once (only opening video files waits for the first
  previews), and returning from a thread or the gallery waits for a running background
  fill before it restores the view. A verified media file is remembered by its full file
  identity, so a file swapped for another of the same size and date is checked again.
- **Diagnostics.** The app writes a rolling per-user log file outside the profile and
  recovers unexpected UI-thread exceptions with a visible error banner. The log and the
  Diagnostics page name the platform, the window title bar mode and where the
  reduced-motion decision came from. When the device time zone cannot be resolved,
  archive date filters say so and use UTC instead of failing.
- **Focus and window fixes.** Closing the export dialog or returning from the gallery
  now puts focus back on the export button, or on **More** when the button sits in the
  closed overflow menu at narrow widths (focus used to be lost). When saving Settings
  fails validation, the visible error line of the field is scrolled into view, also in a
  small window. The About, Settings and first-run windows keep their normal size after a
  restore from the title bar on Linux/X11, where the window manager used to bring the
  old maximized size back. Several dialogs (archive metadata, gallery details, media
  occurrences, reader groups, saved searches, experimental activation, startup error)
  got a larger minimum height so their footer stays visible.
- **Keyboard shortcuts.** Main-page order is Downloads, Archive, Media, Booru | Rules,
  Sources & Plugins | Status. Defaults are **Ctrl+1/2/3** for Downloads/Archive/Media,
  **Ctrl+6** Booru, **Ctrl+4** Rules, **Ctrl+5** Sources & Plugins and **Ctrl+7** Status
  (**Cmd** on macOS). **Ctrl/Cmd+8** is unassigned. Diagnostics and Statistics are Status
  segments without default digit bindings; saved bindings still reach their segment.
  A saved `navigation.plugins=Primary+6` wins over the new Booru default and opens
  **All plugins** on Sources & Plugins. Footer, menus and F1 follow the same page order,
  with effective bindings; an F1 entry does not make a hidden/unavailable page reachable.
  **Tagging** is an app-menu command with no default page digit. Thread tags are **Ctrl+T**
  (Archive and Reader) and media tags are **Ctrl+Shift+T** (tiles on the Media page and the gallery), the thread favorite
  is **Ctrl+D**, filters are **Ctrl+Shift+F** (board filters moved there from Ctrl+Shift+R),
  and **Ctrl+A** selects all media. The large Reader has find next and previous (**F3** and
  **Ctrl+G**, **Shift+F3** and **Ctrl+Shift+G**). The gallery and Media page gain **S**
  slideshow, **I** details, **R** rating, **Ctrl+E** export original and **Ctrl+O** show in
  folder; in the Archive and Downloads **Ctrl+O** still opens the thread folder. One **Back**
  gesture (**Alt+Left**) answers for previous reading position, back to the gallery and back to
  media, innermost first; one page gesture (**Alt+PageUp/PageDown**) pages results, posts and
  backlinks by focus. On macOS the defaults follow Apple conventions (**Cmd** for Ctrl, no
  gesture that needs Fn, **Cmd+Delete**, **Cmd+Left** for Back, **Cmd+G** find next, **Option+Cmd+R**
  refresh, **Control+Cmd+F** full screen, **Cmd+?** help), shortcuts show as ⌃⌥⇧⌘ glyphs, and
  a native menu bar lists them. **Settings, Keyboard shortcuts** has a switch that turns the
  standard single-character shortcuts off (letters, digits, +, −, ?); Space, Enter, arrows,
  Delete, F keys and Ctrl/Alt/Cmd chords stay. **Your saved shortcuts are never changed.**
  Where a new default meets a shortcut you set for another command, the default steps aside
  for that command and the shortcut editor says so; the startup warning appears only for
  bindings that are really blocked.
- **Second interface review.** Archive filters carry a visible label above every field and
  short placeholders; the media favorite button shows a filled star for a marked file and
  keeps its size when a write fails (the reason is in its tooltip); the board wizard
  shows one count line per board ("3 threads in the catalog · 1 to watch · 2 excluded")
  and no "include 0 matches" action; Diagnostics turns off watch actions for a removed
  result and labels a freshly shown page; plugin details move their header actions under
  the title below 900 dip and a plugin problem shows a sentence with the next step (the
  exception text stays in the tooltip); a mistyped link shows a neutral 4chan address as
  the format example instead of the first registered source's; the empty Downloads board
  list offers the clipboard import; saved searches say why Save, Replace, Apply, Rename
  and Delete are disabled; the Archive date field shows its pattern in your language;
  the SHA-256 search names the version flag in plain words; a failed watcher check has a
  sentence in your language; German shortcuts read Strg and Umschalt, and "experimentell"
  and "Anker" replace English words. The cleanup, board admission, filename search,
  import and reader groups windows fit small screens like the other dialogs, the Media
  page heading is a first-level heading like every other main page, and screen readers
  get names for the license list, the URL import report and the board preview.
- **Smaller fixes.** Stale clipboard offers at startup are suppressed, gallery transport
  shortcuts respect nested editors, HTML export titles wrap in narrow dialogs, and
  playback settings and the shortcut editor follow the language. Export and gallery
  actions are enabled only when their selection is really ready, the Downloads filter
  shows true results while starting, and Media page filters keep their identity across
  refills. Local video probes its audio track once per playback instead of on every
  tick, and the bundled VLC runtime is hashed once per process.

  - the large Reader: tools move under **More** from the end of the order Gallery, Read, Find,
    Tags, Export, Full screen, View, History, Capture when the window is narrow, so the HTML export

  - the Booru page, Status segments, Settings and dialogs: optional tools/groups reduce while

  editing them. A view-switch toast can offer **Undo** and **Details** (default 8 seconds,

  changed policy rows without saving or discarding an existing draft. The one-time notice for
  older profiles remains separate.
- **One search field with a scope.** Archive and the Reader's find bar share one search field
  with a scope chip inside it: **Text**, **File name** or **SHA-256**. File name and SHA-256 open
  their existing result dialogs with the draft already searched, SHA-256 keeps its exact
  64-digit check inline, and **Ctrl/Cmd+F** opens the Text scope; **Alt+Down** or **F4** in the
  field opens the scope menu. The Media page's file name search sits at the head of its tools with
  the same chip (one scope, so no chevron). The scope menus carry the query between Archive, the
  open thread and Media, and a different query in the target is offered with **Use it** and **Keep
  current** instead of being overwritten; an empty Archive or Media offers "Search “x” in
  Media/Archive". **Save applied search…** and **Saved searches…** are one split button. The
  query engines are unchanged. Diagnostics, About licences, reader groups, favorites, cleanup, the
  ratings manager and the shortcut editor use the same search box, and Diagnostics gets
  **Ctrl/Cmd+F**.
- **Settings search.** The Settings page has a search field in its header (**Ctrl/Cmd+F**). It
  tolerates typos (`bandwith`), accepts abbreviations and word parts, ignores accents and case,
  knows English and German synonyms for each setting and always matches the English label too. The
  arrow keys move between hits; **Enter** opens the group, unfolds collapsed sections and marks
  and focuses the setting, and **Escape** clears the field first and then leaves it. A polite
  live line announces the hit reached ("n of m: label, group") and an empty result.
- **One Export dialog.** The thread export chooses its format (HTML page or link list) and scope
  (this thread, selected threads, all matches) in the dialog header, and every entry (Archive

  The file is checked through the inventory's own per-file inspection before and after the copy,

  on macOS). Saved shortcuts are never changed.

## Appearance and accessibility

- **MeowChan's own title bar.** Every window and dialog uses the app's own title bar.
  Windows and Linux keep Snap, resize and shadow; Windows 11 gets square corners; macOS
  keeps its native traffic lights, full screen and rounded corners with the app caption
  beneath. `MEOWCHAN_WINDOW_CHROME=system` brings back the platform title bar
  everywhere. The title-bar tagline sits between brand and header display, never pushing
  the graph or window controls. **Interface → Header tagline** offers Off, one fixed quip,
  daily or a new quip per start (default); a shorter form or hiding replaces clipping.
  Its context menu chooses another quip, hides it or opens settings.
- **Animations setting.** **Animations** (Follow system, On, Off; default Follow system)
  decides whether short fades, hover, chip and overlay transitions and the motion of
  notifications are played. Follow system uses the operating system's reduced-motion
  setting. Progress bars and spinners always stay. Menus, flyouts, tooltips and the
  quote preview follow the setting too, and a theme change no longer cross-fades colours.
  `MEOWCHAN_MOTION=off|on` and
  `MEOWCHAN_REDUCED_MOTION=1|0` take precedence over the setting. See
  [Known limitations](#known-limitations) for what was checked.
- **Focus and selection by shape.** The keyboard focus ring is drawn in two shells so it
  stays visible on any background. The selected state shows by shape, not only by
  colour: chips, tiles, thread media tiles (a drawn check mark), the settings sidebar

  for screen readers until revealed, tiles and Danbooru facts have named values, and the
  quote buttons stay reachable with Tab after the post text.
- **Logo by theme.** The light theme shows the orange cat, the dark theme the grey cat,
  switching live in the window icons, tray and dialog icons. The header logo and the About

## Settings, updates and languages

- **Update notice.** When MeowChan finds a new version, a quiet notice appears once per
  start with **Release notes**, **Later** and **Skip this version**, and the tray gets
  the same entry; the footer notice stays as the indicator. A skipped version is not
  announced again, and the notice stays away when information popups are off. With
  automatic update checks off it appears only after your own **Check for updates**,
  which also shows a skipped version again. Nothing is downloaded or installed
  automatically; the release notes open in your browser.
- **Statistics.** Open **Status → Statistics** from the app menu/More or click the
  header display. Ctrl/Cmd+7 opens Status's last-used segment; there is no default
  Ctrl/Cmd+8 Statistics shortcut. It measures MeowChan's own application-payload network
  and media-file I/O, not operating-system totals, headers, TLS overhead, thumbnails or
  archive/index writes. Failed transfers and retries may contribute bytes without a saved
  file. Upload counts completed request-payload writes, not the number of requests.
- **Header I/O directions.** The header has two category graph areas, network and disk,
  not four graphs or combined direction totals. By default its word/rate matrix is
  **Down**, **Up**, then **Read**, **Write**, localized (German: Download, Upload, Lesen,
  Schreiben), with equal-width right-aligned values. It draws no Network/Disk headings.
  Download and read are solid/filled, upload and write dashed; each category has its own
  scale. Rates use at most **three visible digits** with adaptive precision and binary units,
  for example 127 KiB/s, 1.27 MiB/s or 12.7 MiB/s, promoting the unit before four digits
  would be needed. File-size totals are unchanged.

  arrows. Tooltips still name the direction, rate and line style; the full screen-reader

  Network and disk stacked, Network and disk side by side, Text only and **Off, hide the

  Off. The header's context menu exposes the same setting, and Statistics can restore the

  Sampling depends on visible/active consumers; it is not full-system monitoring.

  as download/read/write, with three history graphs (download, disk write, disk read),
  axes and per-source rows; there is no fourth upload-history graph. **Reset statistics**

  30–3600), tray interval (5000 ms, 2000–60000), tray tooltip/menu (on), local persistence
  (on), retention (30 days, 1–365), save interval (5 minutes, 1–60) and source limit
  (64, 8–256). `io-stats.json` keeps daily totals, with optional upload data, atomic writes,

- **Rules page.** The footer lines up with the 880 dip content column and carries the only
  status; a field error is shown at its field, **Save** stays available and the footer names the

  height; template buttons are grouped and selection actions appear only with a selection. The
  Archive and Media filter controls keep a keyboard return path: **Esc** closes the active

## Plugins, sources and SDK 1.1.0

- **Sources & Plugins.** One page lists active sources before inactive ones, with status
  chips, and offers **Sources**, **Image filters** and **All plugins**. Source details keep
  integrity/permission controls and watches; **Plugin details** opens the second level and
  **Back to source** returns without changing pages. Plugin activation, repair and approval
  remain explicit. **Add in Downloads** focuses the shared URL input; the page has no URL
  field of its own. Watch rows show address and status; beyond the configured row count,
  a link opens Downloads. **Add plugin…** and folder sources use this same page.
- **Read-only media folders.** **Sources & Plugins → Folders → Add folder…** registers an
  image/video folder without copying it. Files appear on Media and in the gallery; MeowChan
  does not write, move or rename source files. Folder links, overlapping sources and
  profile/download folders are refused. A scan lists files without hashing; exact SHA-256
  identity is read lazily by the gallery, explicit metadata actions or bounded idle work.
  **Pause reading** stops background hashing; **Look through again** checks the listing.
  Background work does not read online-only cloud placeholders, but explicitly opening
  one may cause its storage provider to fetch it. Metadata lives in the profile's
  `folder-sources.db` and tag/favorite/rating stores, not in source files. Removing a
  folder leaves files alone and retains unavailable metadata; a full catalog can still
  shrink. Changed bytes keep old tags on the old version; copying them to the current
  version is an explicit, confirmed action with undo.
- **Profiles in separate windows.** **⋯ → Profile → New profile…** creates another profile;
  **Switch profile…** opens a known profile in its own window, not over this window's data.
  `MeowChan --profile <folder>` selects one from the command line; an already open profile
  is not started twice. A new profile may receive an existing read-only media folder.
  Path checks run asynchronously; Switch rows show **Checking…** and unusable/unknown
  paths cannot be opened. The shared `profiles.json` list contains folder references
  outside individual profiles; removing an entry deletes neither profile nor media.
- **Toolchain check at startup.** The plugin toolchain is verified outside the build gate, in
  parallel with reading the profile and scanning the plugin inventory, and every verified file's
  identity is re-checked right before the toolchain is used, so other imports and builds no
  longer wait for the hashing.
- **Plugin SDK 1.1.0.** Adds the typed booru post-search contract
  (`SourceCapabilities.PostSearch`, `IBooruSourcePlugin`, typed request, page and post
  results) with before-id cursor paging (`BeforePostId` / `NextBeforePostId`, used by
  sources whose post order is `PostOrderKind.DecimalPostId`), and an explicit
  `PluginDeclarationStatus` (property `DeclarationStatus`) for blocked plugin metadata.
  Hosts accept plugins that declare SDK `1.0.0` or `1.1.0`; final compatibility
  acceptance remains separate. A plugin that declares post search must declare 1.1.0.
- **SDK API review.** The initial SDK review moved the then-unshipped declarations
  to `MeowChan.PluginSdk/PublicAPI.Shipped.txt`; see the
  [initial API review](v1.1.0-api-review.md) and
  [current review/migration notes](v1.1.0-api-review-current-2026-11-14.md) (German). The SDK and library stay explicitly not
  stable in 1.x; the review adds no compatibility promise.
  The booru post identity is named `BooruPostId` (renamed from `SourcePostId` after the
  move to Shipped; the API review notes it). The JSON shape is unchanged. Profile-bound
  Core consumers must migrate from `RestoreAsync` to `StartAsync(lease)`; the old startup
  is intentionally refused, not covered by a blanket binary-compatibility promise.
- **One-time bundled-plugin transition.** A bundled plugin whose only change from the
  approved build is the declared SDK version `1.0.0` to `1.1.0` is activated
  automatically at startup once per plugin, keeping enabled state, settings, filter
  grants, restricted-source permissions and source ownership, without a new rights
  review. It requires an exact description match, the same candidate and path, a
  matching delivery record and valid settings. This SDK-only exception is not reusable
  for later builds; it is separate from the compatible-rebuild path below.
- **Compatible rebuilds and changed declarations.** A proven same-identity in-place
  bundled rebuild can be adopted at startup with current delivery proof, unchanged
  description and valid exact saved configuration. A hash change alone need not cause
  another repair-confirmation/restart loop. This does not silently unpin code, transfer
  special permissions, choose a different candidate or invent legacy provenance.
  Changed capabilities/settings still use **Review bundled repairs** with explicit
  change and, where required, separate permission confirmation. Editing configuration
  clears the change confirmation even if the old value is restored. Manual repair is
  saved for the next start, not live plugin replacement. See
  [Updates of bundled plugins](../plugins/using-plugins.md#updates-of-bundled-plugins) and
  [in-place rebuilds in Help](../Help.md#in-place-bundled-plugin-rebuilds).
- **Plugin approvals.** Reauthorizations you explicitly tick can be submitted together;
  they are written one after another and stop at the first failure. Approval status is
  announced politely to screen readers, and approval texts exist in Spanish, French and
  Russian.
- **Danbooru in the plugin package.** The Danbooru plugin is part of the bundled plugin
  delivery (24 bundled plugins) and is enabled by default; see
  [Danbooru search and watchers](#danbooru-search-and-watchers).
- **More bundled sources.** SevenChan (7chan), BbwChan, 8chan.moe, Fchan and CapybaraChan
  are bundled as experimental sources, disabled until you activate them. AnonImageboards
  and GuroCx are bundled as documented technical blocks without a route or network
  access. No live availability is claimed for any of them.
- **Source fixes.** 2ch (Dvach) stickers, Uboachan deleted-file markers and 7chan
  threads with unquoted post ids or repeated file links are accepted; 7chan multi-file
  posts name their attachments by file name. An attachment
  without a usable extension, or with metadata the host rejects, is skipped and marked
  invalid instead of failing the whole thread. 2ch no longer passes its provider MD5
  as an integrity expectation (the provider's MD5 and size described a different file
  in the observed runs); a stated MD5 is still validated for format, and the file must
  still match its content length, decode and reopen offline.

## Transfers, imports and exports

- **Import transfer packages.** **Inspect transfer package…** in the Archive header opens
  the import dialog: a package is read, verified and staged before any archive write,
  planned as a new thread or a merge into an existing or 404 thread, and applied only
  on explicit confirmation.
  Existing originals, favorites, ratings and notes are not silently replaced. Several
  threads in one set are applied one after another with a partial-result receipt, not
  atomically. Repeating an import is idempotent. Private metadata is not imported
  silently; a package with private data is refused on an explicit new import instead of
  importing only its public part. **Check again** re-reads a package after you changed it
  on disk, without closing the dialog. (Importing your own loose files is described in
  [Importing your own files](#importing-your-own-files).)
- **Media conflicts.** When a merge brings different bytes for the same place, the
  alternative is recorded and can be reviewed in **Manage conflicts**: keep, discard
  (a discarded alternative is not offered again) or use it as the active version, each
  after confirmation. Discarded alternatives whose files nothing references any more
  can be reclaimed from disk after a confirmation that names the folders.
- **Interrupted imports.** At startup, an import or merge that stopped before its
  commit is offered for discarding in a two-step question. Keeping it, pressing Escape or
  closing leaves the strict recovery state.
- **Exports.** HTML exports follow the language set when the export is started, in all 12 interface
  languages (the seven newer texts are AI-authored and not reviewed by native speakers), and use
  the Reader's cards, colours and greentext: reply cards fit their content up to 52 rem, the
  opening post sits on the page and files float beside the text. Every page has a
  **System / Light / Dark** switch that needs no script (nothing is stored; printing always uses
  the light palette) and an **About** button with the thread facts, the MeowChan version, a link to
  grassmann-it.de (the only external link) and the cats Simba and Mila with the photographer's
  credit, shown from `meowchan-cats.png` next to `index.html`. The exports still contain no script,
  load nothing from outside and keep the strict content policy. URL-text export and filename search are
  available from Archive. Copying originals from the Media page is described above.

## Upgrading from 1.0.2

**Close MeowChan and back up your entire profile and media folders first.** Include
`meowchan-import/` in your download folder once you use the file import. Changes below
are made on first start or first use of the new feature. There is no supported
downgrade of data changed by 1.1.0.

**What happens on the first start:**

1. `archive.db` is migrated from schema 5 to 12 in one transaction.
2. The work journal drops rows of superseded media generations, after one checked backup
   (see the table).
3. Bundled plugins take the one-time SDK transition above; the five new experimental
   sources and the two technical blocks appear disabled, Danbooru appears enabled. Local
   `.cs` plugins are recompiled.
4. Your settings are read as before; the new settings start at their defaults, and your
   saved view, shortcuts and plugin choices stay.

The first start creates no `private-tags.json`, `booru-catalog.json` or
`local-imports.json`; each new file appears only when you first use its feature. The
Media page index is built in the background the first time you open the Media page.

**Private tags, version 1 to 2.** The first tag write that touches a loose file converts
`private-tags.json` from version 1 to version 2 (a new section holds the occurrence
registry; archive schema stays 12). It keeps the old file as `private-tags.json.bak` and,
permanently, as `private-tags.v1.bak` (written once, byte-identical, never replaced or
deleted by later writes; the `.bak` is replaced by every later change). Version 1 files
stay byte-identical until then, and later writes keep version 2. Builds that only know
version 1 refuse version 2 and do not overwrite it, and a newer or damaged primary or
backup file is never overwritten or rotated away. To go back to a build that only knows
version 1, close MeowChan and restore `private-tags.v1.bak` as `private-tags.json`; this
loses only the tags on local files and any later tag changes. 1.0.2 itself has no own
tags and ignores both files, so this matters only for builds between 1.0.2 and 1.1.0 that
know version 1.

**Going back.** A downgrade to 1.0.2 is not supported: 1.0.2 refuses the migrated archive
database, so an upgraded profile does not open there. Use a complete pre-upgrade backup
restored to a separate location; do not point 1.0.2 at an upgraded profile. Plugin-state
and tag backups are not full-profile backups (the `.bak` tag backup is replaced by later
writes; only `private-tags.v1.bak` is permanent). Changes made in 1.1.0 after the backup
are not carried back. Going back does not delete saved Danbooru files or imported files,
but whether an older version lists them is not promised.

## Known limitations

- **Platform and native acceptance is still open.** Windows/macOS title bars, native
  menus and shortcuts, reduced motion, NVDA/VoiceOver, 150 % scaling, native playback,
  hardware audio/GPU and packaging still need maintainer acceptance on the relevant
  systems. Compilation and Linux private-display checks do not establish that acceptance.
  **Pending**, see [Release process and evidence](#release-process-and-evidence).
- **Danbooru** is anonymous, read-only and the only provider in this post-search flow.
  Other booru providers, accounts, uploads, voting and remote tag editing are not included.
  Enabling or showing the source alone submits no search; saved active watchers can still
  check on schedule. No live-provider availability or acceptance is claimed.
- **Own-tag scope is limited.** Danbooru media controls remain disabled with a reason.
  Local own tags need a manifest occurrence, an own import or a registered folder-source
  version; arbitrary uninventoried files cannot be tagged. The favorites gallery offers
  no tag target, and orphans have no managed move/re-link. Own tags do not travel with
  transfer packages or original exports; the Export dialog states this.
- **Integrated tagging still needs combined interaction acceptance.** Gallery panel,
  TP3 popovers, TP4 marks, stamp, queue/walk and cards are present. Their integration is
  not a native keyboard/focus/undo or persistence acceptance of this base. The Media page
  and thread media tab retain full dialogs for batch/advanced editing.
- **Video previews and folder reads have limits.** Seek previews need a usable local
  decoder and verified video; source wiring and a configurable cache do not prove native
  hover/playback behavior. Folder scans are not full-file verification, and explicit
  reads of cloud placeholders can trigger the storage provider's own fetch.
- **Transfer limits remain.** Private-metadata imports, rootless packages and stale plans
  stay blocked. There is no user-facing creation of transfer packages beyond the existing
  HTML and original-file exports, nor a settings-import UI.
- **Language reviews are not native-speaker acceptance.** Spanish, French, Russian,
  Simplified Chinese, Japanese, Korean, Brazilian Portuguese, Czech, Italian and Polish
  remain **Untested** preview translations. Language/plural reviews have taken place,
  including Wave3/Wave4 follow-ups; they are not qualified linguistic/native-UI acceptance.
  Some legacy/vendor surfaces still use English. The seven newer HTML-export languages
  likewise have no native-speaker acceptance. CJK display depends on installed fonts.
- **Help is integrated, not globally accepted.** The committed [Help](../Help.md) now
  covers Media, tags, import, Booru, tagging walks, profiles, folder sources and the
  integrated work views. Final runtime/navigation/accessibility and complete language
  review remain separate; missing Help sections are not a current implementation blocker.
- **Contrast and performance evidence has limits.** Palette/unit checks are not a rendered
  real-display audit. Light progress fill does not reach 3:1 on every raised/hover/accent
  surface; no blanket contrast pass is claimed. Synthetic collection measurements and
  cache work are not a speed-up guarantee or a final-commit benchmark.
- **Experimental sources** are not verified against the live sites.
- **Plugin SDK:** the 1.1.0 additions are Shipped in the public API inventory, but the
  SDK stays not stable in 1.x; profile-bound Core startup needs the migration noted above.

## Release process and evidence

**No release acceptance is asserted here.** Integrated code, documentation and test
fixtures are not an exact-source candidate, executed smoke, final package set or
upgrade acceptance. Existing partial evidence remains bound to its own source SHA
and scope in the [1.1.0 status](../release-1.1.0-status-2026-11-11.md); it does not
combine into a pass for the base of these notes. No build, test suite, GUI, provider
request or package gate was run for this documentation reconciliation.

- **Pending:** an exact-source `stable-candidate` run with every required job, the
  original asset set, verified source identity, inventory and `SHA256SUMS`. There is
  no accepted candidate, package verification or release date.
- **Pending:** full suites and registered smokes on the final combined source,
  including tagging, Reader sidebar/inline video, folder sources, profile switching,
  Booru display/lifetime/handoff and Status deep links. Earlier focused passes or
  app builds do not cover every interaction; historical failures remain historical,
  not automatically cleared by later source changes.
- **Pending:** AP04 upgrade and two offline restarts. The runner generates a synthetic
  profile with the pinned published 1.0.2 source, opens it with the candidate three
  times (upgrade plus two offline restarts), then checks writes/readbacks, effective
  settings in all three cycles, permanent byte-identical `private-tags.v1.bak` and
  the downgrade phrases on this page. Tooling is integrated, including the settings
  and qualified-test-name corrections; this is not a completed upgrade run. A
  source-only diagnosis is `SOURCE-ONLY`, never a release pass. The runner's `PASS`
  also requires the matching Linux candidate packages and `SHA256SUMS`; final
  packaged-apphost evidence remains open. No personal profile is used.
- **Pending:** final public API/analyzer/inventory and package-consumer evidence on
  the chosen SHA/package (`scripts/check-public-api.py --release --source-commit <sha>`).
  SDK consumer and synthetic legacy host/childworker intermediate results exist with
  their documented scopes; they do not establish a blanket binary-compatibility or
  release pass. The old profile-bound Core startup is intentionally refused.
- **Pending:** the complete plugin material-change/repair/reauthorization process
  matrix on the final state. Loading an old plugin or passing focused Desktop bridges
  does not prove that changed configuration cannot inherit earlier consent.
- **Pending:** private native GUI/platform checks by the maintainer: Windows, macOS,
  scaling, keyboard/focus, screen readers and physical audio/GPU. Linux unit or
  private-display tests do not replace them; neither do source-only smoke fixtures.
- **Recorded behavior, not a new pass:** application shutdown keeps a requested
  Danbooru original instead of cancelling it. An explicitly cancelled original is
  currently not requeued by a watcher; a later explicit original request overrides
  that cancellation. Any policy change needs its own decision and evidence.
- **Documentation is present, acceptance is separate.** Help and Wave3/Wave4 language
  reviews are integrated. Final documentation accuracy, native-UI language and
  rendered contrast checks remain, without inventing a missing-feature blocker.
