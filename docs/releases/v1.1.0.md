# MeowChan 1.1.0: Media page, own tags, Danbooru and plugin SDK 1.1.0

> **Draft / unreleased.** MeowChan 1.1.0 is not published. There is no release date,
> no tag, no downloadable package, no accepted candidate run and no package
> verification. This page is a working draft of the release notes. Statements describe
> the source as it is documented and tested at the base named in
> [Basis of this draft](#basis-of-this-draft); items that are not yet integrated or
> not yet verified are marked **Pending**. The final text will be written at
> publication.

This is a feature release on top of [1.0.2](v1.0.2.md). It adds a Media page, own
tags, a first Danbooru source with watchers, a larger set of bundled experimental
chan sources and plugin SDK 1.1.0, and it changes several profile files on first
start. Read [Upgrading from 1.0.2](#upgrading-from-102) before you replace an
existing installation.

## Media page and own tags

- **A Media page for everything you saved.** A **Media** button next to Archive shows
  every saved media file across all archived threads as a tile grid, sorted by thread
  (default), newest or random. Filter by tags, type, favorites, rating, source, board,
  file name, thread and, for videos, whether they have sound. Saved files that are
  missing can be shown. The page opens the shown files as a gallery, jumps to the post
  in its thread and returns with **Back to media**. The page reads a derived index;
  the index cache is disposable and rebuilt when damaged or when its version changes.
- **Duplicates are grouped, not merged.** Files with the same SHA-256 appear once with
  an "in N threads" hint that lists every occurrence (source, board, thread, file name,
  own tags, **Show in thread**). Tags stay with each occurrence and are never copied
  between them.
- **Select, tag and export from the page.** Ctrl/Cmd+click, Shift+click and Ctrl/Cmd+A
  select tiles. A selection can be tagged together in one all-or-nothing write, opened
  as a gallery or exported as originals. **Export all shown** exports one original per
  shown tile through the existing export dialog and asks first above 500 files or
  2 GiB. Tiles that are unsaved or have no original are counted as unavailable, not
  skipped silently.
- **Own tags.** Tags are private to your profile and stored in `private-tags.json`.
  Tag a thread from the Reader (tag bar with `/name/` suggestions taken from the title
  and first post) and tag the exact shown media version from the gallery. Threads show
  their tags in the thread list and table. The Archive filter can include or exclude
  tags (all or at least one included), saved searches describe tag filters by name,
  and the **Tag manager** lists thread and media counts, renames tags and deletes them
  after a question that names both counts. Thread and media tags do not inherit from
  each other.
- **Tags protect what they mark.** A thread with an own tag, or with a tagged media
  version, is protected from archive cleanup. Permanently deleting a thread removes
  its tag assignments and reports a failed cleanup instead of hiding it.
- **Tags follow a re-check.** When a source changes what it reports about an attachment,
  tags on the old attachment key are handed over to the new key for the same
  attachment and the same bytes. Different bytes do not inherit tags.

**Pending integration:** tagging of loose and legacy files that are not bound to a
captured post (separate occurrence identity, a registry in `private-tags.json` version
2, one shared target resolver, an orphan check in the Tag manager) is on the
integration branch described below, not on the main development line. It is not part
of the statements above.

## Danbooru search and watchers

Danbooru is a new, bundled, read-only source (`meowchan.official.danbooru`). It is a
post-search source, not a board or thread source. In the intended 1.1.0 behaviour:

- **Search and single posts.** A tag search shows previews, the post link, source tags
  and the provider's own rating. MeowChan does not add an automatic rating filter; a
  rating condition you type stays part of your query. A post link or numeric post id
  loads exactly one post and creates no watcher.
- **Originals only on request.** Searching and selecting load no media. Chosen originals go
  through the ordinary download queue. A post already known from another search,
  one-shot or watcher is not queued twice, and its additional finds stay recorded.
  A sample or preview is never silently used as the original.
- **Watchers.** A saved search can be paused, checked now, resumed or removed. The first
  check sets a baseline instead of downloading the whole history. Checks are bounded
  per run and continue below a post id cursor (`page=b<id>`), so a backlog is caught up
  over several checks without gaps or duplicates and without a page limit.
  A manual check of a paused watcher runs once and leaves it paused; it still honours
  the provider cooldown. After HTTP 429 the watcher waits at least 60 seconds, or the
  provider's longer `Retry-After`, and is kept. Removing a watcher keeps all saved
  media, metadata and finds.
- **Provenance and offline use.** Provider post id and link, rating, score, source
  tags with categories and where each post was found are stored in `booru-catalog.json`,
  separately from your own tags. Requests carry no credentials; a request with
  credentials is rejected by the host. Searching, loading a post and checking a watcher
  need a connection; saved media and stored metadata do not.
- **Not offered:** upload, voting, tag editing, accounts, other booru providers, an
  unbounded backfill and Danbooru-specific own tags (own tags on provider media need a
  new tag target and are shown disabled with an explanation on the integration
  branch).

**Pending:** in the integrated source the Danbooru window is not reachable. The desktop
session does not yet construct the search service, original queue and watcher host
(composition root), `BooruServices` stays unset and the menu entry stays hidden. The
Danbooru plugin is also not yet part of the plugin package list on the main
development line (24 plugins when included; 23 without it). Whether Danbooru is active
by default or opt-in like the experimental chan sources is **undecided**. Display of
downloaded Danbooru media in the Media page, gallery and favorites (source filter,
detail dialog with provider tags kept apart from own tags, offline restart) is on the
integration branch. See [Booru data: upgrading and older versions](v1.1.0-booru-data.md).

## Archive, Reader and gallery

- **Filters accept what you pick.** In Archive filters, clicking a source or board
  suggestion, pressing Enter on it, or choosing a source state adds it immediately as a
  chip, and **Search** adds leftover text in those fields first. Invalid values stay in
  the field with one message under it. Tags still need an explicit include or exclude.
  The Archive and Media filter fields open as a surface over the results instead of
  pushing the list down.
- **Status messages as an overlay.** Archive status messages appear as a timed overlay
  above the docked footers, so the list and reader boxes run to the page edge.
- **Reader.** The Reader toolbar stays on one row and moves its least useful actions
  into **More**. Saved-media tiles show video posters. Posts are separated by a rule
  in the dark theme. Find in a saved thread, filename search and an exact SHA-256
  search entry (for a thread with exactly one media folder) are available from the
  Reader.
- **Gallery favorites.** Keyboard **F** on a saved favorite asks before removing it;
  **U** removes explicitly. A Tags button tags the shown media version.
- **Startup.** Archive, Downloads and Settings are usable while the session is still
  starting; archive reads are separate from writes, which wait for Ready. Downloads
  shows the last known session in its normal table, marked as such, until the first
  authoritative data arrives. Unchanged bundled plugins reuse their validated
  description and bundle verification work, and candidates are probed two at a time.
- **Diagnostics.** The app writes a rolling per-user log file outside the profile and
  recovers unexpected UI-thread exceptions with a visible error banner.

## Appearance

- **Logo by theme.** The light theme shows the orange cat, the dark theme the grey cat,
  switching live in the main window, About, Settings, first-run, startup error, tray and
  the other dialogs. Program and package icons stay orange. THIRD-PARTY-NOTICES
  describe both motifs.
- **Light theme.** Warm grey surfaces and a muted orange accent replace pure white
  panels; dark is unchanged.
- **Dialogs and pages.** Many dialogs use a shared frame with a fixed header, a local
  error strip and a fixed footer around a scrolling body, and Diagnostics, Rules and
  Settings follow the shared page header spacing.
- **Languages.** New texts are present in English, German, Spanish, French and Russian.
  Spanish, French and Russian remain unreviewed machine translations (Untested).

## Plugins, sources and SDK 1.1.0

- **Plugin SDK 1.1.0.** Adds the typed booru post-search contract
  (`SourceCapabilities.PostSearch`, `IBooruSourcePlugin`, typed request, page and post
  results) with before-id cursor paging, and an explicit `DeclarationStatus` for blocked
  plugin metadata. Hosts accept plugins that declare SDK `1.0.0` or `1.1.0`; plugins
  built for 1.0.0 keep working. A plugin that declares post search must declare 1.1.0.
- **One-time bundled-plugin transition.** A bundled plugin whose only change from the
  approved build is the declared SDK version `1.0.0` to `1.1.0` is activated
  automatically at startup once per plugin, keeping enabled state, settings, filter
  grants, restricted-source permissions and source ownership, without a new rights
  review. It requires an exact description match, the same candidate and path, a
  matching delivery record and valid settings. Reverse changes, any additional
  description change, pins, conflicts and any rebuild after a 1.1.0 build was already
  activated (even a failed one) follow the ordinary rules: **Review bundled repairs**,
  explicit authorization, restart. See
  [Updates of bundled plugins](../plugins/using-plugins.md#updates-of-bundled-plugins).
- **Plugin approvals.** Reauthorizations you explicitly tick can be submitted together;
  they are written one after another and stop at the first failure. Approval
  texts exist in Spanish, French and Russian.
- **More bundled sources.** SevenChan (7chan), BbwChan, 8chan.moe, Fchan and CapybaraChan
  are bundled as experimental sources, disabled until you activate them. AnonImageboards
  and GuroCx are bundled as documented technical blocks without a route or network
  access. No live availability is claimed for any of them.
- **Source fixes.** 2ch (Dvach) stickers, Uboachan deleted-file markers and 7chan
  threads with unquoted post ids or repeated file links are accepted. An attachment
  without a usable extension, or with metadata the host rejects, is skipped and marked
  invalid instead of failing the whole thread. 2ch no longer passes its provider MD5
  as an integrity expectation (the provider's MD5 and size described a different file
  in the observed runs); a stated MD5 is still validated for format, and the file must
  still match its content length, decode and reopen offline.

## Transfers, imports and exports

- **Import transfer packages.** **Inspect transfer package…** in the Archive header opens
  the import dialog: a package is read, verified and staged before any archive write,
  planned as a new thread or a merge into an existing or 404 thread, and applied only
  on explicit confirmation.
  Existing originals, favorites, ratings and notes are not silently replaced. Several
  threads in one set are applied one after another with a partial-result receipt, not
  atomically. Repeating an import is idempotent. Private metadata is not imported
  silently.
- **Media conflicts.** When a merge brings different bytes for the same place, the
  alternative is recorded and can be reviewed in **Manage conflicts**: keep, discard
  (a discarded alternative is not offered again) or use it as the active version, each
  after confirmation.
- **Interrupted imports.** At startup, an import or merge that stopped before its
  commit is offered for discarding in a two-step question. Keeping it, pressing Escape or
  closing leaves the strict recovery state.
- **Exports.** HTML exports follow the language set when the export is started. URL-text
  export and filename search are available from Archive. Copying originals from the
  Media page is described above.

## Upgrading from 1.0.2

**Close MeowChan and back up your entire profile and media folders first.** Changes
below are made on first start or first use of the new feature. There is no supported
downgrade of data changed by 1.1.0.

| What | What happens | Older versions |
| --- | --- | --- |
| Archive database `archive.db` | Schema `user_version` 5 to 12 on first open, in one transaction. Version 12 adds the media conflict ledger. | A 1.0.2 build refuses it as an unsupported schema. |
| Media manifests | Newly written manifests use version 5 (6 when an import or merge stores derived representations). Older records are still read. | Not tested; do not expect 1.0.2 to read them. |
| Work journal `work-state.sqlite` | Once per start, before watches are restored, rows of superseded media generations are removed. Before the first deletion the journal is copied with a checked `VACUUM INTO` to `work-state.before-prune.sqlite`. There is one backup file; it is replaced only when a later start deletes again. If the backup fails, nothing is deleted and the start continues with a warning. Schema stays `user_version` 1. | Open the journal as before. |
| `private-tags.json` | New file, created at the first tag write (no 1.0.2 counterpart). | Ignored. |
| Media index cache `media-index-v1.json` | Derived cache, rebuilt when absent, damaged or of another version. | Ignored. |
| `booru-catalog.json` | New file, created when Danbooru data is first saved. Schema 1; a damaged, oversized or newer file is refused and never overwritten or treated as empty. | Ignored. |
| Bundled plugins | New build bytes and SDK declaration; the one-time transition above applies. Plugin approvals and the v2 plugin-state envelope from 1.0.2 stay. Seven further experimental plugins and, when packaged, Danbooru appear as new entries. | See below. |
| Local plugins (`.cs`) | Recompiled, because the SDK fingerprint changes. The one-time exception applies to bundled plugins only; rights of a rebuilt local plugin follow the ordinary review rules. | |
| 2ch archives | The first re-check of an archived 2ch thread downloads each original once more because the attachment key changes with the MD5 change. Assets are reused (no second file or tile); favorites and ratings stay; own tags are handed over to the new key. | |

**Pending integration:** on the integration branch, the first tag write that touches a
loose file converts `private-tags.json` from version 1 to version 2 and keeps the old
file as `private-tags.json.bak`; older versions refuse version 2. Version 1 files stay
byte-identical until then, and `private-tags.json` did not exist in 1.0.2, so this
affects only profiles written by development builds. The same branch raises the media
index cache version.

**Going back.** Use a complete pre-upgrade backup restored to a separate location; do
not point 1.0.2 at an upgraded profile. Plugin-state and tag backups are not
full-profile backups. The new profile files are listed above; going back does not
delete saved Danbooru files, but whether an older version lists them is not promised.

## Known limitations

- **Danbooru is not reachable yet** in the integrated source (see Pending above), is
  anonymous, read-only and limited to the bundled provider. A third-party plugin can
  declare post search, but only the bundled Danbooru source is used by the host.
- **Own tags on files outside a captured post, and on Danbooru media,** are not available
  on the main development line. Files outside every thread manifest have no inventory
  and cannot be tagged. There is no shared media context menu in every view yet and the
  favorites gallery offers no tag target. Own tags do not travel with transfer packages;
  the Export dialog states this.
- **Import of private metadata, rootless packages and stale plans stays blocked.** There
  is no user-facing creation of transfer packages in this release line beyond the
  existing HTML and original-file exports.
- **Spanish, French and Russian** are unreviewed machine translations.
- **Experimental sources** are not verified against the live sites.
- Plugin SDK 1.1.0 additions are moved to Shipped in the public API inventory after
  the review in `docs/releases/v1.1.0-api-review.md`; the decided rename of
  `SourcePostId` to `BooruPostId` is applied there too. This closes only the inventory
  gate, not a release check.

## Release process and evidence

Nothing below is a pass. No exact-source `stable-candidate` run, package inventory,
checksum verification or upgrade run from a real published 1.0.2 profile exists for 1.1.0.
Developer test runs on individual commits are partial evidence and do not combine into
an acceptance of a different commit. In particular:

- **Pending:** one exact-source `stable-candidate` run with all required jobs and the
  original asset set, root verification of source identity, inventory and checksums.
- **Pending:** upgrade from a real 1.0.2 profile with two offline restarts. The synthetic
  1.0.2 profile generator has not completed successfully, so the archive 5 to 12 and
  journal pruning checks are synthetic only.
- **Pending:** integration of the composition root, shared media menu, loose-media tags
  and Danbooru media views, then a full test and smoke run on the integrated commit.
- **Pending:** public API review and the Unshipped to Shipped move for SDK 1.1.0
  (`scripts/check-public-api.py --release` rejects the SDK Unshipped entries until then).
- **Pending:** an application shutdown during an active Danbooru original transfer used
  to record the original as permanently cancelled. The queue was changed so that a stop is
  not a cancel, but the acceptance test for it is still skipped in the test project.
- **Pending:** Windows, macOS, 150 % scaling, screen reader, physical audio/GPU and
  everyday-use checks by the maintainer. Linux unit and private-display tests do not replace them.
- **Pending decisions:** Danbooru default-on or opt-in; whether an aborted original is
  re-queued when a watcher finds it again; wording of "watcher".
