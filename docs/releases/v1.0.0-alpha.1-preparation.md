# Preparing 1.0.0-alpha.1

This is the maintainer checklist, not the public release body. Public text:
[v1.0.0-alpha.1.md](v1.0.0-alpha.1.md).

Requested on 23 October 2026: an optional early preview, with 0.9.0 remaining the
stable recommendation. Prepare a GitHub **draft**, marked **prerelease**, with
`make_latest=false`. Do not upload old validation packages under the alpha name.

## Initial source boundary

## Before building the alpha candidate

1. Integrate the parallel work with its owner and freeze the intended source.
   Record the exact commit; update the draft target and known limitations to match.
2. Set shared `Directory.Build.props` Version to `1.0.0-alpha.1`. Remove the
   stable-version overrides in `MeowChan.PluginSdk`, `MeowChan.PluginHost` and
   `MeowChan.PluginCompiler` so they inherit it. SDK/Host sample package defaults
   should follow the actual package version. **Keep `SdkContract.Version=1.0.0`:**
   it is the independent plugin protocol contract, not the release channel.
3. Regenerate affected project-reference lockfile ranges for normal and RID
   graphs, without upgrading dependencies. The existing `[1.0.0, )` project
   ranges do not describe prerelease project packages.
4. Teach `scripts/package-macos.py` to accept a validated SemVer prerelease.
   Keep Apple's numeric bundle fields numeric and preserve full alpha identity
   in product metadata and filenames. Add focused packaging regression coverage;
   its current test deliberately rejects beta versions.
5. Build and test the exact frozen candidate. Serialize all .NET/build/runtime
   probes with `/tmp/meowchan-ui-1.0-build.lock`; use isolated test profiles.
   Earlier local PASS results belong to their recorded snapshots, not this future
   alpha candidate. Close or explicitly reassess the known Reader regressions
   and native accessibility limitations before writing final release claims.

## CI and assets

- Push the candidate branch, then dispatch `dotnet-desktop.yml` with
  `mode=validate`, `platform=all`, `scenario=all`. A tag exactly matching
  `v${Version}` also passes the existing version gate.
- The workflow retains Actions artifacts; it does not publish a GitHub release.
  Linux distribution packages require the separate `linux-distribution` or
  `package-media` dispatch. Bind every binary/source companion/checksum to the
  exact candidate and originating run.
- **Do not dispatch `upload-verified-release.yml` for the alpha.** That workflow
  and `assemble-stable-release.py` are intentionally specific to 0.9.0 and its
  accepted retained inputs. Use a separate alpha inventory/upload process.
- Verify shipped product identity, bundled compiler/plugins, native video
  payloads, matching legal/source companions and SHA256SUMS before attaching
  assets. Do not relabel the older Linux plugin E2E package as this alpha.
- Replace any provisional branch links in public notes with the final tag or
  candidate commit. Attach only actual available downloads; do not promise
  platform packages that have not been produced.

## Draft and publication checks

Verify draft target, `draft=true`, `prerelease=true`, and no automatic/latest
promotion. Publish only after candidate and assets are coherent; publication
must keep `prerelease=true` and `make_latest=false`. Recheck
`GET /repos/tfgrass/MeowChan/releases/latest` still returns `v0.9.0`.

The in-app update checker already orders alpha SemVer correctly and excludes
prereleases by default. Alpha users must opt into prerelease checks to discover
later alphas; do not silently change that preference as part of this draft.
