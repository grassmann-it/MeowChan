# MeowChan 0.9.0 screenshot provenance

These 16 PNGs are unedited renders of the integrated MeowChan UI from two source-built DesktopSmoke captures. The Barebones and Advanced comparison images show the same six passive Downloads rows and selected thread in two real views. They, along with the refreshed gallery, Settings and Rules images, came from the provided Release harness binary corresponding to functional source checkpoint `be2f807eeedaf783a152de6f0501d5742beb324b`. The later `b0888df` commit promoted screenshots and changed release documentation without changing application source or capture binaries. The other 11 images retain their original capture from source commit `b8e129146e1d8d3d26108fbee00aa881ae2ac5ea` (Git tree `9ce0630e1f649c3d1bf0b0a3e5a65f52e6743f9c`) and their original provenance below. All five final images were visually reviewed and are byte-identical to their capture files.

Both runs passed on Manjaro Linux in a private 3200×2000 Xvfb display with Openbox, private DBus/runtime directories and software rendering. Requested and measured RenderScaling were **1.0**. Main-window scenes use Dark/English; the comparison images show Barebones and Advanced, while the other workspace scenes use Simple. Captures exclude native window decorations. About, favorites and export dialogs retain their actual client sizes. The fixed temporary paths visible in some dialogs belong solely to the isolated showcase workspace; there are no personal profiles or downloaded posts.

`ShowcaseData` seeds 56 synthetic archived threads and 173 captured posts with saved, original procedural Skia illustrations. Its HTTP handler rejects network requests. Downloads shows passive demonstration projections; the gallery, reader, archive, favorites and HTML/original exports use real local application services. The gallery image is marked as a favorite in the running UI, and the original-export result reports one copied file. The Reader shows archived posts and a disabled Live-follow control as appropriate for a thread without an active watch; the separate Replies image shows locally resolved replies. About shows the configured PayPal support link, Credits and the offline Feather license inventory.

This is **source-built UI evidence**. It does not establish native acceptance of extracted Windows, macOS or Linux release packages, physical-device playback, host integrations or live provider behavior.

## Final Barebones, Advanced, gallery, Settings and Rules

The final capture used the existing Release DesktopSmoke binary, without a rebuild, in a fresh isolated output directory:

```sh
mkdir -p /tmp/mc-final-t
TMPDIR=/tmp/mc-final-t \
PATH=/tmp/meowchan-ui-tools/usr/bin:$PATH \
LD_LIBRARY_PATH=/tmp/meowchan-ui-tools/usr/lib \
XDG_DATA_DIRS=/tmp/meowchan-ui-tools/usr/share:/usr/share \
python3 scripts/run-desktop-smoke.py \
  --assembly /home/tomka/Desktop/oChan/tests/MeowChan.DesktopSmoke/bin/Release/net10.0/MeowChan.DesktopSmoke.dll \
  --mode visual --scale 1 --output artifacts/release-final-showcase --timeout 180
```

Retained local evidence: `artifacts/release-final-showcase/results.json` (SHA-256 `2284068fd8cba303c16dec45350069f48cc286d3a586b897a585954714c60af6`) and `visual/output.log` (SHA-256 `f98b97038796e652818140bc7bb56427877f035e4ee01b21cfcda4cc7d097807`). The result records PASS at 1.0 scale. The capture DLL SHA-256 values were `f07a3dbecd2c0b8b236a7358dff554994d030595ace94632be0b18720f7d6cd6` (`MeowChan.DesktopSmoke.dll`), `aa3d2c9be0d965b1d550d68feffd9bee2f940e6e85376e0f4a2f5e21fac61bcc` (`MeowChan.dll`) and `3818693674b06099ab1c1d4cea6801f8fe0251f9117ec8b5a8713f44b78c5343` (`libmeowchan.dll`). The new reader capture omitted a lower thumbnail during rendering, so the complete original reader image was retained.

The comparison scenes are generated by `ComparisonCaptures` from six passive thread snapshots. Barebones uses an 880×680 client window with its details panel closed; Advanced uses a 1380×850 client window with the same first row selected and its details panel open. No provider watches or HTTP requests were made. The shorter Barebones header and denser table, and the separate Advanced fields and details, are actual view behavior rather than edited mockups.

## Original capture for the other 11 images

The source-built **Debug** DesktopSmoke DLL was prepared from commit `b8e129146e1d8d3d26108fbee00aa881ae2ac5ea` with a locked restore and build in the isolated artifacts directory:

```sh
dotnet restore tests/MeowChan.DesktopSmoke/MeowChan.DesktopSmoke.csproj \
  --artifacts-path artifacts/r09-showcase-b8e1291 -r linux-x64 --locked-mode
dotnet build tests/MeowChan.DesktopSmoke/MeowChan.DesktopSmoke.csproj \
  --artifacts-path artifacts/r09-showcase-b8e1291 -r linux-x64 --no-restore -v minimal
```

The frozen DLL was then captured in a fresh isolated output and temporary directory. The short temporary path keeps private DBus socket addresses within the Unix path limit. The exact capture invocation was:

```sh
mkdir -p /tmp/mc-b8-t
TMPDIR=/tmp/mc-b8-t \
PATH=/tmp/meowchan-ui-tools/usr/bin:$PATH \
LD_LIBRARY_PATH=/tmp/meowchan-ui-tools/usr/lib \
XDG_DATA_DIRS=/tmp/meowchan-ui-tools/usr/share:/usr/share \
python3 scripts/run-desktop-smoke.py \
  --assembly /home/tomka/Desktop/oChan/artifacts/r09-showcase-b8e1291/bin/MeowChan.DesktopSmoke/debug_linux-x64/MeowChan.DesktopSmoke.dll \
  --mode visual --scale 1 --output artifacts/r09-showcase-b8e1291/capture2 --timeout 180
```

The three `/tmp/meowchan-ui-tools` overrides supplied private GUI prerequisites for this host; systems with Xvfb, Openbox and DBus tools installed normally can omit them. Retained local evidence: `artifacts/r09-showcase-b8e1291/capture2/results.json` (SHA-256 `2284068fd8cba303c16dec45350069f48cc286d3a586b897a585954714c60af6`) and `visual/output.log` (SHA-256 `0f7d2fcd42e4af06415c279a2c15992c9e4a1dd70b5a0e7ea9a1dc714d4625d8`). The result records PASS, 1.0 scaling, normal window close and no binding errors. The visual log confirms seven complete reply buttons inside the expanded post viewport.
