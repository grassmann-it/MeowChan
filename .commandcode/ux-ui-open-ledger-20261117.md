- 2026-11-17 UX-LEDGER-15 root cause found by code audit (Kimi K3.1, full table at `$COMMANDCODE_SCRATCHPAD/astra/overlay-hover-audit-kimi.md`): `OnOverlayPointerExited` calls `RememberPointer`, which never clears `_lastPointerScreen`, so the exit's `PointToScreen` maps to the last valid IN-WINDOW client point (`GalleryViewer.Overlay.cs:569-572`). `GalleryEdgeHit.At` therefore still returns `Post`, the 250 ms tick keeps refreshing `_lastPostActivity`, `_hoverContextOpen` can never close, and a stale `_pointerOnPostIndicator` keeps the indicator visible AND hit-testable — an invisible click blocker. Focus loss does not help because `SetInteractionAvailable(false)` calls `RevealOverlayControls` (`Playback.cs:101-115`) and hiding requires `ActiveWindow && !Popup`, so E/W/F/M/P are all retained. Fix: treat a routed root exit as outside (never infer "inside" during PointerExited), clear every hover-bought flag, and use one unconditional transient-release method on deactivation/minimize/popup. Eight further surfaces ranked with evidence; quote preview, reader enlarge and video scrub already cancel their async work correctly, media tiles / filmstrip / rating-star preview / bottom chrome do not release at all. Named test gap: no test covers the enter → native edge leave transition (`GalleryOverlayActivityTests.cs` only covers hit-zone math and inactivity).
